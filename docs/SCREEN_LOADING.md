# 공통 화면 로딩 팝업

MAITE의 화면 조회 안내를 `ScreenLoadingProvider`와 `useScreenLoading(active)`로 통합한다. 기존 writing-loading.png와 글쓰기 팝업의 레이아웃을 재사용하고 문구는 “불러오는 중…” 하나만 표시한다. 취소/사용량 버튼이나 화면별 로딩 설명은 추가하지 않는다.

## 적용

- 초기 로그인 확인/연결, 계정 조회, 최초 캐릭터 이미지 캐시 준비.
- 캐릭터·소설 상세 조회와 캐릭터 대화/이야기 복원·열기.
- 서점 목록/새로고침·구매한 콘텐츠 열기, 서고 구매 목록·구매한 회차 읽기.
- 보상 달력/월 이동, 마이페이지 알림 설정 조회와 계정 수동 새로고침.

화면 진입용 데이터 조회만 연결한다. 알림 주기 동기화, 자동 저장, 캐릭터 썸네일 재검증·개별 지연 이미지 로딩에는 팝업을 띄우지 않는다. 소설·이미지 생성과 대화 스트리밍은 기존 인라인 스피너를 유지하며 생성 때문에 팝업을 띄우지 않는다. 오류/빈 목록/서비스 이용 불가 안내는 로딩 설명과 다르므로 유지한다. 레거시 CAD 기술 화면은 변경하지 않는다.

## 동작

웹 `/ideal` 레이아웃과 하이브리드 앱 진입점에 동일 provider를 둔다. 여러 화면 조회가 겹치면 요청별 토큰을 등록하고 마지막 요청이 끝날 때까지 하나의 dialog만 유지한다. 각 hook은 완료·실패·화면 이탈 시 토큰을 해제한다. 캐릭터 복원은 요청 당시 경로를 함께 확인해 다른 메뉴에 오래된 로딩이 남지 않게 한다.

150ms 이내의 짧은 조회는 팝업 없이 완료해 깜빡임을 줄인다. dialog는 배경 조작을 막고 키보드 포커스를 유지한다. 진행 중 Escape/Android 뒤로가기로 임의로 닫지 않으며, 조회 완료/실패 또는 브라우저 경로 이동에 따른 해제로 닫힌다. 오류 시 팝업을 닫아 기존 오류/재시도 안내를 사용할 수 있게 한다.

구매한 소설의 목록→본문 조회는 이어지는 로딩으로 처리한다. 데이터 성공 여부나 기존 과금/저장/API 정책은 바꾸지 않으며 추가 AI 호출은 없다.

## 검증

모의 API 브라우저 테스트로 겹친 캐릭터 복원 요청의 팝업1개 유지, 이미지 실제 로딩, Escape 유지, 조회 성공/실패 후 해제, 이전 화면 이동, 배경 알림 조회 팝업 미표시를 확인한다. 기존 가입·서고·구매 회차·보상 달력·서점·이미지 확인 팝업도 함께 검사한다. 모바일 화면 캡처는 `.verification/screen-loading.png`다.

타입 검사·단위182개·관련 계정 화면9개·전체 웹39개·모바일1개·Next.js 빌드 통과. 모바일 번들 생성과 Android 동기화를 완료했다. 실제 유료 AI 호출·운영 DB 변경·운영 배포는 수행하지 않았다.
