# 소설 생성 시간 개선

`novel_develop.md` 13절의 단일 호출 설계를 구현하되, 독립 검수의 품질 비교를 하지 않은 상태에서 이를 제거하지 않도록 기본 경로와 실험 경로를 구분했다. UI·클릭당 한 회차·5편 구간·컨셉 변경 후 전역 번호 이어쓰기·공유 기억·하트 정책은 유지한다. 모델과 추론 설정은 변경하지 않았다.

## 기본 경로에 적용한 개선

`OPENAI_NOVEL_GENERATION_MODE=reviewed`가 기본값이다. 미설정/오타도 이 경로를 사용한다.

- 공유 사건의 반복 필드명과 원고 출처 ID/본문을 `columns`/`rows` 형태로 전송한다. 모든 사실·근거·인물·지식 범위·순서를 보존하며, 짧은 자료나 새 필드가 있는 자료는 기존 표현을 유지한다. 저장된 원문/스냅샷/출처 ID 검증은 바꾸지 않는다.
- 독립 검수에서 재작성할 원고는 `memoryPatch:null`로 응답할 수 있다. 폐기할 요약·기억까지 생성하지 않도록 한다. 검수 항목과 근거는 유지하며, 채택할 원고의 기억은 여전히 필수다. 통과 판정인데 기억이 없으면 저장하지 않고 실패 처리한다.
- 기존 중간 회차 플롯 재사용, 검수/기억 추출 결합, 근거 있는 문제에만 한 번 재작성하는 정책을 유지한다.
- 정상 원고의 분량이나 검수 기준을 낮추거나, 더 빠른 모델/낮은 추론으로 바꾸지 않는다.

이 최적화는 입력의 반복 구조와 폐기 출력량을 줄인다. 모델의 생성 속도 자체를 보장하거나 실제 대기 시간이 특정 비율로 줄었다고 의미하지 않는다.

## 선택 가능한 단일 호출 경로

로컬/배포 서버 환경변수에 다음을 설정하면 다음 요청부터 적용한다. 로컬 서버가 환경변수 변경을 반영하지 않으면 다시 시작한다.

```dotenv
OPENAI_NOVEL_GENERATION_MODE=integrated
OPENAI_NOVEL_INTEGRATED_MAX_OUTPUT_TOKENS=12000
```

| 상황 | reviewed 기본 경로 | integrated 실험 경로 |
|---|---:|---:|
| 새 작품/새 구간 첫 회차 | 3회 | 2회 |
| 같은 구간 2~4회차 | 2회 | 1회 |
| 같은 구간 5회차 | 3회 | 1회 |
| 오류 보정 | 최대 +2회(재집필+독립 검수) | 최대 +1회(전체 묶음 보정) |
| 완결 후 변경 없는 추가 요청 | 0회 | 0회 |

단일 호출 응답에 본문·현재 전역/구간 회차·자체 검수·기억 패치를 함께 받는다. 기존 회차 플롯은 재사용하고 첫 구간/추가 컨셉에만 별도 설계한다. 기획·검수·기억은 화면에 표시하지 않는다.

첫 회차가 실패하면 기존의 완료 시점 저장 정책에 따라 미확정 플롯도 커밋하지 않는다. 따라서 다음 사용자 재시도에서 플롯 설계가 다시 필요할 수 있다. 플롯만 먼저 별도 저장하는 DB 계약으로 변경하지는 않았다.

코드는 아래를 검사하고 성공한 원고와 기억만 기존 완료 이벤트로 함께 반환한다.

- 스키마와 전역/구간 회차 번호
- 정리된 본문이 비어 있는지 확인
- 직전 원고의 대규모 복제
- 자체 검수의 설정 충족/문제 여부와 완결 조건
- 검수·사건·관계·인물 기억의 인용 근거가 실제 본문에 있는지

오류에는 한 번만 보정한다. 두 번째 실패·취소·불완전 응답은 회차를 증가시키지 않는다. 출력 토큰 한도 초과/네트워크 오류는 유료 호출을 자동으로 반복하지 않는다. 기존 생성 작업 ID의 멱등 처리와 캐릭터별 생성 잠금을 재사용하며 DB 스키마 변경은 없다.

**중요한 한계:** 자체 검수는 독립 편집자 호출과 같지 않다. 코드로 모든 인과관계·성격 표현·복선·설정의 의미를 판정할 수 없으므로, 단일 호출 경로가 같은 품질이라고 보장하지 않는다. 이 때문에 현재 `.env.local`의 기본 동작은 reviewed를 유지한다. 비교 후 복귀하려면 `OPENAI_NOVEL_GENERATION_MODE=reviewed`로 설정한다. 두 모드는 이야기의 전개에 맞춰 분량을 조절한다.

## 계측과 비교

- 기존 `ai-usage`에 호출별 시작·소요 시간·입력/출력/추론/캐시 토큰이 기록된다. 통합 응답은 `novel.episode_bundle`로 구분한다.
- `novel-completed`에는 모드·회차·호출 수·보정 횟수·서버 생성 소요 시간·전송한 지침/입력의 문자 수·본문 글자 수를 기록한다. 원고나 캐릭터 프로필은 기록하지 않는다.
- `inputChars`는 지침+입력 문자열의 문자 수이며 스키마/실제 토큰 수와 같지 않다. 서버 생성 시간은 DB 저장·클라이언트 렌더링을 포함한 전체 클릭 시간과 구분한다.
- 같은 장르·인물·필수 사건·분량으로 두 경로를 여러 번 비교해야 한다. p50/p95와 함께 설정 준수·성격·한국어·인과관계·결말·재시도 비율·전체 소비 토큰을 평가한다. 호출 수 감소를 대기 시간/비용의 같은 비율 감소라고 해석하지 않는다.
- 이번 자동 검사는 모의 응답으로 호출 수·검증·실패 보존·완결·구간 재시작·기억 공유를 확인한다. 실제 유료 모델의 지연/품질 비교나 원격 배포는 수행하지 않는다.
- 합성 메타데이터 예시(공유 사건12개·원고 출처45개)는 6,014자에서 4,417자로 줄었고 원래 데이터를 복원할 수 있음을 확인했다. 이는 해당 메타데이터 표현의 문자 수이며 전체 요청 크기·실제 토큰·생성 시간 감소율이 아니다.

검증 결과: 타입 검사·단위152개·전체 웹39개·모바일 화면1개·Next 배포 빌드 통과. 모바일 빌드와 Android 동기화도 완료했다. 통합 API에서도 한 회차만 반환하고 실패한 본문/기억을 공개하지 않는 검사를 포함한다. 현재 연결 설정은 reviewed, gpt-5.4-mini, 집필 medium, 검수 low이며 변경하지 않았다.
