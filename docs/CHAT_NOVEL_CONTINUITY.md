# 채팅·소설 성격과 공유 기억 분석 및 적용

기준 문서: 루트 `chat_develop.md`, `novel_develop.md`. 이번 변경은 성격의 반응 반영과 양방향 사건·관계 공유에 집중하며, 기존 UI·스트리밍·클릭당 한 회차 생성·추가 컨셉 입력 흐름을 유지한다.

## 기존 흐름과 확인한 한계

- `app/api/chat/route.ts`는 채팅과 소설의 진입점이다. 채팅은 한 번의 Structured Outputs 호출로 대사·말투·발화 의도·기억 패치를 함께 생성한다. 성격 원문과 일반 지침은 전달하지만 구체적인 동기·말버릇·지속적인 감정의 원인/목표를 저장하는 구조는 부족했다.
- `lib/chat/memory.ts`는 출처가 있는 사실과 짧은 감정 enum을 유지한다. 사용자 문장 ID를 실제 문장으로 복원하고 근거 없는 추측이나 제3자의 가상 행동은 거른다.
- `lib/chat/timeline.ts`는 두 모드가 같은 객체를 참조하지만 장소·관계·약속 중심이었다. 중요한 일반 사건은 공유 대상에서 빠졌고, 같은 인물의 새 관계가 다른 기존 관계까지 지울 수 있었다. 소설의 다른 인물 관계를 채팅에 전달할 때 지식 범위를 구분하기도 어려웠다.
- `lib/novel/generate.ts`는 첫 회차에서 5편 플롯을 설계하고 클릭당 한 편을 집필한다. 이후 저장한 플롯을 재사용하며 원고 검수와 기억 추출은 한 호출로 결합되어 있다. 근거가 있는 문제에만 최대 한 번 재작성한다.
- `LiveChat.tsx`는 완료 신호까지 새 기억·회차·시간선을 임시 보관하고 성공 시 함께 적용한다. 같은 캐릭터의 채팅/소설 생성 잠금과 시간선 revision 검사도 이미 있다. `snapshot.ts`의 JSON 스냅샷은 같은 시간선과 캐릭터별 기억을 Supabase documents 및 로컬 저장에 보존한다.

## 적용한 구조

### 성격·감정

`lib/chat/personality.ts`에서 명시적인 성격/컨셉으로부터 핵심 특성·동기·취약점·말버릇을 파생한다. 별도 모델 호출 없이 기존 채팅 호출의 비공개 기억 패치에 포함한다. 파생 프로필은 최초 한 번만 저장하고 입력 설정이 달라지면 다시 만든다. 성격 단어를 코드에서 특정 말투나 행동으로 고정 매핑하지 않는다.

발화 근거가 있는 기쁨·불안·질투·호감, 친밀감·신뢰, 현재 목표와 직전 감정 원인을 저장한다. 수치 범위와 턴당 변화량을 제한한다. 수치는 보조 신호이고 명시적 관계와 성격보다 우선하지 않는다. 프로필과 감정은 `chatMemory.personality`로 저장하며, 실패·중단·다른 캐릭터로 전환할 때 임의로 초기화하지 않는다. 성격 수정 시 기존 사건과 감정의 연속성을 보존하고 파생 특성/목표만 재평가한다.

프롬프트는 직접 반응 → 성격에 맞는 해석/선택 → 필요한 후속 화제 순서를 지시한다. 상담형 범용 질문, 무조건적인 맞장구, 매 턴 질문과 동일 말버릇 반복을 줄이며 선택된 존댓말/반말은 유지한다. 소설 집필에도 동기와 선택으로 성격을 보여주는 지침을 적용한다.

### 공유 사건 기록

`timeline.canon`에 사건·관계·약속·지속 상태를 보관한다. 출처(chat/novel), 턴/회차, 주체/대상, 안정적인 키, 예정/진행/완료/취소, 지식 범위(public/character/reader), 요약과 근거가 있다.

- 채팅 → 소설: 검증된 최신 기억 패치의 중요한 사건과 관계 변경을 공유한다. 가정·농담·추측은 정본으로 승격하지 않는다. 약속은 실행되기 전까지 예정이다. 사용자 주장은 발화 출처를 유지하며 전지적 객관 사실과 구분한다.
- 소설 → 채팅: 기존 검수 호출에서 `sharedChanges`를 함께 추출한다. 원고의 source ID를 실제 근거로 복원하고, 성공한 회차만 공유 기록에 병합한다. 다른 인물만 아는 비밀과 독자에게만 공개한 정보는 reader로 기록한다.
- `timelineForChat()`은 reader 정보를 모델 입력에서 제외한다. 소설에는 전체 기록을 제공해 비밀과 인물 지식을 구분한다. 등장했다는 이유만으로 모든 사건을 안다고 취급하지 않는다.
- 아직 알려지지 않은 인물의 이름은 숨기고 내부 ID만 예약한다. 새 채팅 인물이 같은 ID를 재사용하면 해당 기억을 거절한다. 사용자가 숨겨진 인물을 직접 이름으로 언급하면 기존 ID에 연결하지만 그 인물의 비밀 사건은 계속 제외한다.
- 같은 주체·대상·키의 새 기록은 현재 상태를 대체하며 다른 관계는 유지한다. 최신 소설 사건과 충돌하는 이전 채팅 기억은 모델 문맥에서 제외한다. 채팅이 바꾼 현재 상황은 다음 회차에서 이어가며 오래된 플롯을 현재 사실보다 우선하지 않는다.
- 기록은 최대 12개, 전체 시간선은 7,200자 이내다. 오래된 상세 사건은 순환 정리한다. 원문 전체나 끝없는 이벤트 로그를 매 요청에 보내지 않는다. 기존 장면·관계·약속 필드도 호환한다.

## 유지한 계약과 적용 범위

- UI, 하트 정책, 모델/추론 설정, 버튼 한 번당 한 편 생성 방식은 그대로다.
- 컨셉을 입력한 생성 클릭은 기존의 명시적인 방향 변경+생성 결합 동작이다. 전역 회차는 이어지고 `seriesStartChapter` 기준 새 5편 구간의 발단부터 시작한다. 기존 원고를 수정하지 않는다.
- 별도 AI 호출·새 DB 테이블·SQL 마이그레이션은 없다. 기존 JSON 스냅샷에 선택 필드를 추가하여 옛 저장 데이터도 읽는다. 입력/출력 메타데이터가 늘어 실제 토큰이 조금 증가할 수 있으며, 호출 수가 그대로라는 것을 토큰 소비가 동일하다는 뜻으로 해석하지 않는다.
- 문서의 별도 방향 변경 화면/구간 UI, 추가 논리·언어 검수 호출, 2,500~3,000자 강제 분량 정책 등은 이번 요청의 성격·기억 개선과 분리했다. 현재 UI와 기존 회차 파이프라인/분량 정책을 바꾸지 않았다.

## 검증 범위

단위·통합 검사는 성격 프로필 재사용/설정 변경, 근거 없는 감정 변화 거절, 스냅샷 복원, 가정 제외, 구별되는 관계 보존, 출처가 있는 사건 양방향 전달, 독자 비밀의 채팅 입력 제외, 실패 시 기억/회차 미반영, 추가 호출 없음, 기존 회차·새 구간 보존을 확인한다. 브라우저 검사는 두 모드 간 상태 연결과 실패 후 재시도를 확인한다.

검증 결과: 타입 검사, 단위146개, 전체 웹39개, 모바일 화면1개, Next 배포 빌드 통과. 모바일 번들 빌드와 Android 동기화도 완료했다. 비밀 인물 ID 예약·새 인물의 충돌 거절·이름 직접 언급 이후에도 비밀 유지 검사를 포함한다. 운영 배포나 원격 DB 변경은 하지 않았다.

실제 생성 품질은 고정 응답 테스트와 구분해야 한다. 이번 검증은 유료 모델을 호출하지 않는다. 같은 입력으로 성격이 다른 캐릭터들의 반응·자연스러움·후속 화제와 여러 회차의 연속성을 비교하는 사용자 평가가 필요하다. 모델이 근거 문장을 의미적으로 잘못 해석하는 모든 경우를 코드만으로 차단한다고 보장하지 않는다.
