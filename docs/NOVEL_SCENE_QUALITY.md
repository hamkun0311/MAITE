# 회차별 장면·대사 정합성

> 최신 구현은 [지침 복잡도 검토와 통합](NOVEL_PROMPT_COMPLEXITY.md)을 따른다. 아래 Scene/Meaning/Causal 이름은 개선 이력이며, 현재는 `quality.ts`의 공통 원칙과 단계별 task로 통합했다.

## 위치·위험·소품·시간 연결 보완

사용자 공유 회랑 장면에서 도착하지 않은 창가에서 빠져나오는 이동, 단순 주의 분산을 수색 종료로 처리하는 결과, 경비 옆에서 들키지 않는 대화, 남은 리본과 수색 결과의 불일치, 시간 전환 뒤 같은 만남으로 돌아오는 모호함을 확인했다. 저장 원고를 조회하거나 수정하지 않았다.

공통 Mechanics 원칙을 수정해 모든 장르의 집필·재작성·독립 검수·integrated 자체 검수에 적용한다. 별도 규칙 묶음이나 검수 단계를 추가하지 않는다.

- 중요한 위치 변화는 실제 도착/퇴장과 가능한 경로로 연결한다.
- 주의 분산과 위험 해소를 구별한다. 탈출·수색 종료 등 결과에는 그것을 가능하게 한 행동이나 문맥상 근거가 있어야 한다.
- 중요한 소품이 남았는지, 이동/회수됐는지와 인물의 시야·청취 가능성이 장면 결과와 맞아야 한다.
- 시간 생략과 과거 장면으로의 복귀는 별개 만남을 같은 순간처럼 읽지 않게 연결한다.

일상적인 이동 생략·설득력 있는 장면 밖 결과·의도적으로 남긴 위험은 허용한다. 모든 동작을 중계하거나 소품을 반드시 회수하고 위기를 반드시 해결하도록 강제하지 않는다. 중요한 연결이 빠졌을 때만 현재 원고의 출처와 최소 보정안을 기존 movementsConsistent/actionsCoherent 판정으로 전달한다. 이전에 없던 사건을 과거 사실로 추가하지 않는다.

프롬프트 버전은 `novel-progress-v21-scene-bridges`다. 기존 회차 생성 방식·모델·추론·출력 한도·분량·UI·하트 정책과 최대 1회 보정은 유지한다. 단위 회귀에는 여러 장르의 누락 사례 다섯 개와 생략/미해결 위험/명시된 시간 전환의 정상 사례를 추가했다. 모의 응답으로 출처 기반 보정과 정상 2호출, 기존 상태 보존을 확인하며 실제 AI의 판단 정확도를 보장하는 테스트는 아니다.

검증: 타입 검사, 단위 테스트 175개, 웹 회귀 39개, Next.js 배포 빌드 통과. 실제 유료 생성·운영 DB 조회/수정·운영 배포는 하지 않았다.

## 사건에 근거한 대사·비유·인과

사용자가 공유한 판타지 원고에서 반박의 대상/가정이 모호하고, 물리적인 손/시선/얼굴의 부재를 나열한 비유가 감정·결심으로 이어지는 근거를 생략하는 문제가 있었다. 본문에는 부상자만 제시됐으므로 동료의 죽음/납치를 실제 사건으로 추정해 고치지 않는다. 궁수 수의 연결, 공격 수단, 돌격과 손실/비판의 인과도 확인 대상으로 삼았다. DB는 조회하지 않았다.

novelCausalRules/novelCausalReviewRules를 모든 장르의 집필·재작성·독립 검수·선택형 integrated 자체 검수에 연결한다.

- 반박은 누구의 어떤 주장에 답하는지, 자신의 행동을 옹호하는지 후회하는지 명확해야 한다. 모호한 지시어와 가정은 필요한 최소한만 풀어 쓴다.
- 감정적 비유와 새로운 결심은 앞선 실제 사건·인물·충족되지 않은 바람에 연결한다. 문맥에서 뜻을 복원할 수 없다면 감정의 의미를 명료하게 하며, 비유 자체를 없애거나 새로운 사건으로 메우지 않는다.
- 현재 부상·생존과 사망·납치를 구분한다. 가정/예측/의심은 이미 발생한 사실이 아니다. 보정을 위해 이전에 없던 사망·납치·가해자를 만들어내지 않는다.
- 중요한 인원의 수·상태·처리 순서가 결과와 이어지도록 한다. 새 회차 안에서 기존 인물의 빠진 행동을 자연스럽게 잇는 것은 허용하지만, 이미 확정된 과거를 새 사건으로 바꾸지 않는다. 모든 인물의 행동을 상세 중계할 필요는 없다.
- 공격은 가용 무기·능력·행동으로 이해 가능해야 한다. 선택과 손실/비판도 인과가 있거나, 부당한 비난이라는 인물의 관점으로 구별돼야 한다.

기존 sceneAudit의 rolesStable에 인물 수/부상·생존 상태, speechIntentClear에 반박 대상/감정 의미, actionsCoherent에 공격 수단/선택과 결과를 포함한다. 현재 원고의 출처와 수정안이 있는 문제만 기존 보정 경로로 전달한다. 명확한 비유·의도된 의문·근거 있는 가정법·일부러 편향된 비난은 허용한다.

추가 검수 호출·출력 필드·추론 강도·모델·분량·가격·UI·기존 원고는 변경하지 않는다. 지침 추가로 입력 토큰은 증가할 수 있다. 회귀 검사는 합성 모험/전투/활극/가족극 사례의 기존 보정 경로와, 가정적인 사망 가능성을 실제 사망 기록으로 만들지 않는 정상 통과 경로를 확인한다. 실제 모델의 모든 의미 오류 탐지를 보장하는 검증은 아니다.

## 5회차 피드백: 부정·상태 소유자·기존 관계

사용자는 4회차에 연인으로 발전하는 과정이 있다고 확인했다. 따라서 5회차의 연인 관계를 새로 근거 없는 관계 상승으로 판단하지 않는다. 공유 원고만 참고하며 기존 원고나 DB는 조회·수정하지 않는다.

`novelMeaningRules`와 `novelMeaningReviewRules`는 모든 장르의 집필/재작성·독립 검수·선택형 integrated 자체 검수에 공통 적용한다.

- 강조형 부정: “아끼는 사람 아니고, 내 편”처럼 함께 성립할 수 있는 내용을 강화하려다 기존 사실을 부정하지 않는다. 의미에 따라 추가/한정으로 표현한다. 실제 거절·반박이나 배타적인 범주 구별은 계속 허용하며 특정 접속 표현을 금지하지 않는다.
- 상태 소유자: 아픈 사람·피곤한 사람·두려운 사람이 누구인지 발화자 전환과 생략된 주어를 따라 확인한다. 상대의 상태를 화자에게 옮기거나 새로운 부상·상태를 만들어 해결하지 않는다. 필요한 최소 주어만 명확히 한다.
- 행동과 의도: 위로하려는 접촉이 의도치 않게 상대를 못 벗어나게 하는 통제로 묘사되지 않도록 한다. 이야기에서 의도한 강압·비유 자체를 제거하는 규칙은 아니다. 이동 제약도 실제 상태/보조 수단으로 판단하며 모든 부상자가 걷지 못한다고 가정하지 않는다.
- 기존 관계: 이전 원고·확정 기억·공유 시간선에 성립한 연인 관계·합의·경계는 유지한다. 현재 회차에서 같은 고백이나 합의를 반복할 필요는 없다. 실제 관계 변화·번복만 새 근거를 확인한다. 공적인 발언도 대상과 내용이 불명확할 때만 명확히 한다.

새 검수 항목이나 호출은 추가하지 않고, 기존 sceneAudit의 rolesStable에 상태 소유자/기존 관계, speechIntentClear에 의미 부정/생략 주어, actionsCoherent에 접촉 의도/힘, movementsConsistent에 이동 제약을 포함한다. 기존 출처 기반 최대1회 보정·실패 시 기존 상태 유지 정책을 사용한다. 지침 추가로 입력 토큰은 증가할 수 있다. 추론·출력 한도·모델·분량·UI·가격은 유지한다.

합성 회귀 사례로 부정/상태 전이/위로-통제 모순의 현재 회차 보정 경로를 확인하고, 이미 연인인 두 사람과 실제로 맞는 부정 표현은 정상 호출 수로 통과하며 기존 관계 사실이 보존되는지 검사한다. 고정 응답 테스트이므로 실제 모델이 모든 의미 오류를 탐지한다고 주장하지 않는다.

## 후속 개선: 모든 소설의 장면·문장 의도 검사

사용자가 이후 공유한 회차에서도 방문 주체 반전, 혼잣말/질문의 불분명함, 의도와 맞지 않는 손동작이 반복됐다. 병실 전용 예시를 공통 집필 지침에서 제거하고 모든 장르에 다음 순서를 적용한다. 이후 원고 검토는 사용자가 공유한 본문만 사용하며 별도로 DB에서 원고를 조회하지 않는다.

1. 장면 전체에서 인물별 역할·위치·목표·행동 제약을 먼저 정리한다.
2. 문장별 발화자·수신자 또는 혼잣말·행동 주체/대상·질문의 의도·이동 목적지를 연결한다. 허락 요청, 확인, 스스로의 기대/예측을 구별하며 특정 어미를 일괄 치환하지 않는다. 손을 내려놓는 것과 상대에게 내미는 것처럼 의도와 동작이 다르면 대상·거리·자세를 자연스럽게 명확히 한다.
3. 결말의 감성적인 대사까지 같은 역할과 제약이 유지되는지 다시 확인한다. 정당한 장면 전환·역할 변화·이해 가능한 함축과 비유는 허용한다.

검수의 `sceneAudit`에는 `rolesStable`, `speechIntentClear`, `movementsConsistent`, `actionsCoherent` 네 불리언을 명시한다. 실제 독립 검수 요청과 integrated 응답 스키마는 이 필드를 필수로 요구한다. 기존 review 데이터 파서는 선택 필드로 호환하며 저장 원고/기억 구조는 변경하지 않는다.

독립 검수는 `pass=true`여도 네 항목 중 하나가 false면 원고·기억을 확정하지 않는다. 현재 원고의 출처 근거와 수정안이 있으면 기존 최대1회 재작성에 실패 항목도 전달하고 다시 검사한다. 근거가 없으면 추측에 따른 유료 재작성을 하지 않고 실패 처리한다. integrated도 실패한 sceneAudit를 통과시키지 않으며 기존 모드의 제한된 보정 정책을 유지한다.

이는 새로운 검수 API 호출이나 고정된 장면 출력 기능이 아니다. 기존 호출 안에서 집필 지침과 구조화된 검수 결과를 강화한다. 추가 지침·네 불리언의 입력/출력 토큰은 증가할 수 있으나 별도 호출 단계와 정상 호출 수는 늘리지 않는다. 실제 모델의 의미 판단을 코드만으로 완벽히 보장할 수는 없다.

회귀 검사는 회사·판타지·추리·여행 설정에서 각 항목의 실패가 전체 pass보다 우선하고, 근거 있는 오류만 현재 회차를 고치며, 이전 상태가 유지되는지 확인한다. 통합 모드의 감사 누락/실패 거절도 검사한다. 실제 유료 생성이나 DB 조회·원고 수정은 수행하지 않는다.

## 1·2회차 검토

사용자가 제시한 병실 소설과 연결 계정의 동일 소설 1·2회차를 읽기 전용으로 확인했다. 기존 원고·기억·회차·DB는 수정하지 않는다.

| 회차 | 확인한 문제 | 보정 기준 |
| --- | --- | --- |
| 1 | 복도에서 부르는 동료에게 “금방 올게요” | 상대와 목적지를 확인한다. 복도로 갈 때의 답변과 병실 안 사람에게 돌아오겠다는 약속을 구분한다. |
| 1 | 간호사가 입원자에게 “내일도 올 거지?” | 방문자와 기다리는 사람의 역할이 바뀌지 않도록 질문과 답을 함께 확인한다. |
| 1 | “침대 끝에 발을 모았다”, “불을 낮게 껐다” 등의 모호한 표현 | 몸·가구의 위치와 실제 뜻을 분명히 한다. 단순 취향 차이는 재작성 사유로 삼지 않는다. |
| 1·2 | 평범한 업무 요청을 근거 없이 사적인 접근/핑계로 단정 | 행동 근거를 제시하거나 특정 인물의 의심으로 한정한다. 정당한 업무와 개인적 압박을 구별한다. |
| 2 | 퇴장이 없는데 “다시 커튼 안으로 들어왔다” | 대사 방향 전환을 실제 이동으로 오해하지 않는다. 귀환 전 이동이 있었는지 확인한다. |
| 2 | 간호사가 환자의 병실을 “제 병실”로 표현 | 입원한 공간과 담당하는 병실을 구별한다. 담당 병실이라는 문맥이 명확하면 오류로 단정하지 않는다. |
| 2 | 입원자에게 “좀 더 오래 있어 줘” | 떠날 예정인지, 함께 이야기하거나 깨어 있어 달라는 뜻인지 확인한다. 애정 표현 자체를 금지하지 않는다. |
| 1→2 | “그날 밤”과 “오늘은 늦었네”로 재방문 시점이 모호함 | 같은 밤의 재방문인지 다음 날인지 필요한 연결을 제공한다. 새로운 날을 무조건 강제하지 않는다. |

## 적용

`novelSceneRules`를 원고 집필과 재작성의 공통 지침에 넣는다. 인물 역할·위치·이동 제약·발화자·수신자·목적지를 내부적으로 확인하도록 한다. 오다/가다를 일괄 치환하거나 특정 직업/대사를 금지하는 문자열 규칙은 추가하지 않는다.

독립 검수는 기존 `previousProse`(직전 회차 전체)와 현재 원고, 확정 기억·공유 시간선을 비교한다. 따라서 2회차 생성 시 1·2회차를 확인하고, 3회차 생성 시에는 2·3회차와 누적 기억을 확인한다. 5편 완성 대기나 매번 과거 모든 회차 재전송은 추가하지 않는다. 이전 원고의 잘못된 한 문장을 새로운 직업·거주·방문 사실로 확장하지 않는다.

현재 원고에서 근거가 있는 역할/이동/문답 오류는 기존 continuity/dialogue 문제로, 의미가 깨진 표현은 language 문제로 보고한다. 현재 원고의 출처 ID와 구체적인 수정안을 요구하고, 기존 최대 1회 재작성 경로로 전달한다. 재검수 통과 후에만 새 회차 원고와 기억을 반영한다. 이전 확정 회차나 기존 DB 원고를 뒤에서 수정하는 기능은 추가하지 않는다.

선택형 integrated 모드에도 장면 자체 검수 지침을 연결하되 근거는 해당 모드의 정확한 원고 인용 형식을 유지한다. 별도 독립 검수를 추가했다고 설명하지 않는다. 추가 API 단계·추론 강도·출력 한도·UI·가격은 변경하지 않는다. 지침이 추가돼 호출당 입력은 소폭 증가할 수 있지만, 정상 생성의 호출 수와 최대 재작성 횟수는 유지한다.

## 검증 한계

고정 응답 회귀 검사는 1회차 원문을 검수에 전달하고, 2회차의 잘못된 이동 대사·방문 역할·입원 역할을 근거로 현재 원고만 1회 보정하며 기존 상태를 바꾸지 않는지 확인한다. 이는 검수 연결과 보정 정책의 검증이다. 실제 모델이 모든 문맥 오류를 발견하거나 동일 품질을 보장한다는 의미는 아니다. 실사용 유료 생성·기존 소설 자동 수정은 수행하지 않는다.
