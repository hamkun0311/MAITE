# 대화·이야기 새로고침 복원

웹은 선택 캐릭터를 메모리에만 보관해 새로고침하면 `/ideal/story`, `/ideal/chat`에서 캐릭터 생성 안내가 나타났다. 기존 복원 함수는 완료 후 항상 생성/수정 화면으로 이동하므로 그대로 재사용해도 읽던 경로를 유지할 수 없었다.

계정별 `sessionStorage`의 `maite-active-character:<userId>`에 마지막으로 연 캐릭터 문서 ID만 기록한다. 대화·이야기에 직접 진입하거나 새로고침할 때 현재 계정의 보유 문서와 대조한 뒤 기존 저장 원고·대화·페이지·이미지를 복원한다. 기록이 없거나 삭제된 캐릭터이면 현재 보유 목록의 첫 캐릭터를 사용한다. 캐릭터가 여럿이어도 유효한 마지막 선택이 목록 순서보다 우선한다. 저장소에는 원고/이미지/인증 토큰을 추가하지 않는다.

자동 복원은 완료 후 경로를 바꾸지 않는다. 복원 중에는 로딩을 표시하고 실패하면 캐릭터 목록에서 다시 선택하는 안내를 표시한다. 로딩 중 다른 메뉴/새 작성으로 이동하면 늦은 복원 응답이 화면이나 작성 폼을 교체하지 않는다. 개발 모드의 effect 재실행에서 취소된 이전 요청이 로딩 상태를 덮어쓰지 않도록 기존 요청 순번을 확인한다. 새 캐릭터 + 버튼의 초기화와 수동 캐릭터 선택 동작은 유지한다.

가입용 `ProfileSetup`은 이미 나이를 수집하지 않고 있었다. 생성 안내로 잘못 이동하면 캐릭터 설정의 나이 입력이 보이는 상황과 구별했다. 가입/프로필 폼의 안내를 닉네임·성별·선택 사진으로 명확히 하고 프로필 수정 초기값에서도 사용자 나이를 전달하지 않는다. 기존 저장된 계정의 나이는 호환성을 위해 읽을 수 있으나 입력/표시하지 않는다. 캐릭터 설정의 나이는 별도 필드다.

회귀 검증은 직접 진입/새로고침 후 대화·소설 페이지 유지, 다중 캐릭터 마지막 선택 복원, 지연 로딩/실패/다른 메뉴 이동, 신규 작성 초기화, 가입 전후 새로고침 및 사용자 나이 미수집을 모의 API로 확인한다. 기존 UI·생성/하트 정책과 서버 인증은 유지하며 AI 호출을 추가하지 않는다.

타입 검사·단위175개·웹39개·관련 계정 화면4개·모바일 화면1개·Next.js 빌드 통과. 모바일 번들 및 Android 동기화를 완료했다. 실제 유료 AI 호출·운영 DB 변경·운영 배포는 수행하지 않았다.
