# 메뉴 이동 후 이미지 재사용

캐릭터 목록은 이미지 주소 목록이 도착해야 CachedImage를 만들었으며, 메뉴 재진입 때 목록을 비웠다. 주소 API의 읽기 캐시는 15초이고 서명 URL은 5분이다. 이미지 파일 자체에는 이미 메모리 24시간, Cache Storage 7일 캐시가 있었지만 화면이 주소 응답을 먼저 기다렸다. CachedImage는 마운트마다 표시용 Blob URL을 생성하고 해제했으며 디코딩까지 이미지를 숨겼다. 화면의 로딩만으로 파일이 재다운로드됐다고 판단할 수는 없다.

## 변경

- 캐릭터 ID/생성 작업 ID로 CachedImage를 즉시 만들고 주소가 없어도 메모리·기기 캐시부터 읽는다. 캐시가 없으면 주소 응답 이후 다운로드하며, 캐시만 찾는 요청의 실패가 정상 다운로드와 합쳐지지 않도록 분리한다.
- 이미지 주소 목록은 계정별 공통 메모리에서 재사용한다. 4분 이후에는 화면의 이미지를 유지하며 새 목록을 요청한다. 초기 썸네일 준비도 같은 목록을 공유하고 기기에 있는 파일은 먼저 사용한다. 새 캐릭터 저장 시 새 이미지가 목록에 없으면 재조회 대상으로 표시한다.
- 표시용 Blob URL과 디코딩 완료 여부를 계정·이미지 ID별로 재사용한다. 서명 URL만 변경돼도 기존 이미지를 숨기지 않는다. 해제된 화면의 이미지는 최대 16MB·60개·24시간 범위에서 최근 사용 순으로 보관한다. 사용 중인 URL은 용량 초과만으로 해제하지 않으며 소비자가 놓으면 정리한다. 파일 캐시의 기존 64MB·100개 예산과는 별도다.
- 메모리 파일 적중 시 기기 저장 큐에 불필요한 쓰기 확인을 추가하지 않는다. 다른 캐릭터의 이미지를 임시 대체 이미지로 쓰던 경로도 제거했다.
- 계정 전환/로그아웃 시 표시용 URL을 해제하고 목록·메모리 캐시를 지운다. 진행 중인 로딩은 이전 계정의 표시 캐시를 다시 채울 수 없다. 기존 기기 캐시의 계정 격리·로그아웃 삭제와 서버의 소유권 검사를 유지한다.

## 확인 범위

회귀 테스트는 6분 후 메뉴 복귀의 동일 Blob URL·다운로드 1회, 새로고침 후 이미지 목록 API와 원격 이미지에 접근하지 못하는 조건에서 기기 캐시 복원, 표시 캐시의 계정 격리·용량 초과 시 사용 중인 URL 보호·중복 해제 방지, 로그아웃 시 이전 Blob URL 접근 실패를 검사한다. 네트워크와 이미지 데이터는 테스트 대역이며 실제 사용자 기기의 체감 지연 개선율을 측정한 결과는 아니다.

캐시가 없는 최초 이미지, 용량 제한으로 정리된 이미지, 기기 저장소에서 제거된 이미지는 다시 다운로드한다. 웹과 하이브리드 앱의 공통 코드를 사용하며 CDN·DB·이미지 생성 품질은 변경하지 않는다.
