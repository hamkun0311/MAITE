# 소설 대사 보정과 채팅 토큰 절약

## 캐릭터 대화의 조건·부정과 감정 방향

사용자가 공유한 “기다렸다/보고 싶었다” 뒤 “오면 심심하다”라는 응답은 조건이 뒤집혀 앞선 감정과 어긋난 사례다. `lib/chat/prompt.ts`의 짧은 `chatMeaningInstructions`를 캐릭터 대화 생성에 한 번만 전달한다. 최근 이력과 의도한 응답을 기준으로 행동 주체·조건(if/unless, 도착/부재)·부정/비교 범위, 문장 사이의 감정·의도·시점을 발화 전에 내부적으로 확인한다. 설명이나 검수 결과를 대사로 노출하지 않는다.

문자열의 “오면”을 무조건 “안 오면”으로 고치지 않는다. 캐릭터의 실제 거절·양가감정·이해 가능한 장난과 말투는 유지하고, 모순을 없애려고 새로운 애정이나 감정을 만들어내지 않는다. 원고를 일괄 조회하거나 과거 대화를 수정하지 않으며, 소설의 네 항목 검수/재작성 단계를 대화로 가져오지 않는다. 대화 개선은 사용자가 요청한 사례 범위에서 진행한다.

추가 API 호출·자동 재시도·검수 출력 필드·스트리밍 지연용 버퍼링·모델/추론/2000 출력 한도·하트 정책은 변경하지 않는다. 지침은 850자 이내이고 요청당1회 포함되도록 검사한다. 지침 추가에 따른 입력/추론 토큰 변화는 가능하며 실제 소비와 품질은 후속 생성에서 확인해야 한다.

회귀 검사는 실제 API 조립 경로에 전체 최근 이력과 공통 지침이 전달되고, 조건에 맞는 응답/진짜 거절/장난의 테스트 응답이 가공 없이 단일 호출로 스트리밍·완료되는지 확인한다. 고정 응답 테스트이므로 실제 모델이 의미 반전을 항상 탐지한다고 보장하지 않는다. 기존 합성 요청의 지침 13,000자 예산과 성격 캐시/말투 유지 검사를 보존했다. 의미 검사는 utterances 밖에 노출하지 않되 필수 JSON/기억 응답 스키마를 유지한다.

## 소설 대사

서로 다른 두 화자가 존댓말/반말을 다르게 쓰는 것 자체는 오류가 아니다. 같은 화자가 같은 상대에게 이유 없이 말을 바꾸는 경우와 질문·답변의 뜻이 이어지지 않는 경우를 구분한다.

- 집필/검수에 `KOREAN DIALOGUE QUALITY` 지침을 공통 적용한다. 질문의 의도·생략된 주어·부정 표현·시간 상태를 먼저 해석하고 자연스러운 한국어로 쓰도록 한다. ‘너도 말해줘야지’처럼 앞에 없던 상호 질문을 전제하거나 ‘내 문자엔 안 늦게 보잖아’처럼 뜻이 흐릿한 표현은 문맥에 맞춰 고친다. 특정 문구를 무조건 치환하거나 장난·의도적인 회피를 전부 오류로 취급하지 않는다.
- `storyState.dialogueRegisters`에 화자/상대별 말투와 원고 근거를 저장한다. 새 회차에 전달하며 다른 화자/상대의 말투를 덮어쓰지 않는다. 기존 저장 데이터는 이 필드가 없어도 읽는다.
- 이미 정해진 말투를 바꾸려면 `changeEvidence`에 원고 속 전환 근거가 필요하다. 검수의 출처 ID를 서버가 실제 원문으로 복원한다. 근거 없는 전환은 기존 보정 경로로 보내고, 해결되지 않으면 기존 회차를 유지한다. 인용이나 일시적인 흉내는 영구 말투 변경으로 저장하지 않도록 지시한다.
- 검수 유형에 `dialogue`와 `language`를 추가했다. 의미가 어긋난 문답, 같은 화자/상대의 근거 없는 말투 변경, 부자연스럽거나 뜻이 불명확한 한국어를 실제 원고 근거로 지적할 수 있다. 기존의 한 번 재작성 상한과 최종 검증은 유지한다.
- 소설 집필에 채팅 전용 성격 지침(짧은 직접 대사만 출력 등)이 섞였던 부분을 소설용 인물 묘사 지침으로 분리했다. 소설의 서술과 여러 인물의 대화 형식은 유지한다.

기본 reviewed 모드는 독립 검수에서 보정한다. integrated 실험 모드는 자체 검수와 코드 검사로 처리하므로 독립 검수와 품질 동등성을 보장하지 않는다. 코드가 모든 문장의 의미·발화 의도·인물 식별을 이해한다고 설명하지 않는다.

## 채팅 입력/출력 비용

최근 성격·연속성·기억·장면 지침을 합치는 과정에서 같은 규칙과 예시가 여러 곳에 반복되고 있었다. 대화별 실제 토큰은 입력·출력·추론·캐시·실패 후 재시도를 나누어 봐야 한다. 이번 조회 시 대상 계정의 최근 chat 작업 기록은 없어서, 사용자가 관찰한 ‘3배’ 구간의 정확한 구성은 확인하지 못했다.

적용한 절약:

1. 실제 채팅 API에 짧은 전용 캐릭터 지침을 사용한다. 소설 전용 전개 설명과 중복된 출력 예시를 매 턴 보내지 않는다. 이름/컨셉 우선순위, 성격, 말투, 실제 기능 한계, 동의·연령 경계는 유지한다.
2. 기억 추출 지침과 성격 지침을 압축한다. 출처·행동 상태·인물 ID·정정·약속·비밀 보호와 기존 기억 병합은 유지한다. 사용자가 대화에 들인 정보를 지우는 방식이 아니다.
3. 현재 설정에 맞는 성격 프로필이 이미 저장됐으면 출력 스키마에서 profile을 null로 제한한다. 매 턴 같은 프로필을 다시 작성하는 선택지를 제거하고 감정/목표 변경만 허용한다. 설정이 바뀌면 새 프로필을 만들 수 있다.
4. 최근 메시지 수/문맥 상한·모델·추론·출력 상한은 변경하지 않는다. 별도 요약/검수 호출을 추가하지 않는다.

같은 짧은 합성 요청에서 실제 API 조립 결과를 네트워크 모의 처리로 비교했다.

| 항목 | 이전 | 적용 후 |
|---|---:|---:|
| 처음 대화의 지침 문자 수 | 21,275 | 약 12,043 |
| 처음 대화의 출력 스키마 문자 수 | 4,839 | 4,839 |
| 저장된 성격 프로필 사용 시 스키마 | 4,839 | 4,265 |

지침 부분은 약43% 줄었다. 이는 **문자 수이며 전체 토큰이나 요금이 43% 줄었다는 뜻이 아니다.** 한국어 프로필·공유 사건·대화 길이에 따라 입력 크기가 달라진다. 추론 토큰과 모델 출력량도 따로 변동하며, 실제 지연 시간·문학적 품질의 전후 비교는 미실행이다.

`chat-context` 로그는 지침/스키마/최근 대화 문자 수, 사실/공유 사건 개수, 프로필 재사용 여부만 남긴다. 원문·프로필·키는 기록하지 않는다. 기존 토큰 사용량 메뉴와 `ai-usage`의 실제 입력/출력/추론/캐시 수치로 변경 후 같은 작업을 비교할 수 있다. 실패/재시도로 이미 소비된 토큰도 합계에 포함해야 한다.

## 저장과 검증

SQL 변경은 없다. 선택적인 JSON 스냅샷 필드와 기존 API·회차 완료 처리를 재사용한다. 과거 생성 원고는 자동 수정하지 않으며 새 생성부터 적용한다.

자동 검사는 화자/상대별 말투 유지, 전환 근거, 한국어/대사 오류의 제한된 재작성, 기존 회차 보존, 성격 스키마 재사용, 입력 크기, 최근 대화의 무손실 전달과 기존 공유 기억/중단 오류 방어를 확인한다. 모의 응답 검사는 실제 모델의 한국어 품질 평가와 구분한다.

검증 결과: 타입 검사·단위158개·전체 웹39개·모바일 화면1개·Next 배포 빌드 통과. 모바일 번들 빌드와 Android 동기화도 완료했다. 실제 유료 모델 비교나 운영 배포는 하지 않았다.
