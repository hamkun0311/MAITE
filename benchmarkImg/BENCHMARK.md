`index.html`을 브라우저로 열면 화면별 이미지와 확인 팝업을 한 번에 비교할 수 있습니다. 각 PNG도 개별적으로 열 수 있습니다. 첫 로고/스플래시 이미지는 사용자가 직접 제작하므로 생성하지 않았습니다. 로그인 화면의 maite는 배치 확인용 임시 텍스트입니다.

## 화면 흐름

- 사용자 제작 로고 화면 → Google 로그인
- 첫 접속 → 닉네임·성별·나이 입력 → 내 캐릭터 목록
- 기존 접속 → 내 캐릭터 목록
- 캐릭터 선택 → 해당 캐릭터의 대화 목록 / 소설 목록
- 대화 선택 → 대화방
- 소설 선택 → 회차별 읽기 / 완결 작품 판매
- 서점 → 캐릭터 거래 / 완결 소설 거래
- 스토어 → 하트 구매
- 마이페이지 → 계정·닉네임·성별·나이·보유 하트

하단 탭 순서는 **캐릭터 / 뉴페이스 / 서점 / 스토어 / 마이페이지**로 고정합니다. 서점은 콘텐츠 거래, 스토어는 하트 충전으로 역할을 나눕니다. 대화·소설 목록을 별도의 전역 탭이나 마이페이지 목록으로 중복 배치하지 않습니다.

로그인·최초 프로필 입력 중에는 아직 이용 가능한 메인 탭이 없으므로 공통 하단 탭을 표시하지 않습니다. 확인 팝업을 열면 뒤의 콘텐츠와 탭은 조작할 수 없는 배경이 됩니다.

## 확인 팝업의 금액 규칙

| 동작 | 표시 내용 |
| --- | --- |
| 하트 구매 | 100하트 / 2,000원 / 충전 후 1,105하트 |
| 캐릭터 생성 | 사용 50하트 / 생성 후 955하트 |
| 소설 회차 생성 | 사용 15하트 / 생성 후 990하트 |
| 대화 장면 생성 | 사용 30하트 / 생성 후 975하트 |
| 소설 삽화 생성 | 사용 50하트 / 생성 후 955하트 |
| 캐릭터 판매 등록 | 판매금액 30 / 수수료 -5 / 구매 1건당 수령 25하트 |
| 완결 소설 판매 등록 | 회차당 판매금액 10 / 수수료 -2 / 회차당 수령 8하트 |

- 판매 등록 자체로 판매 수익을 즉시 지급하거나 잔액을 차감하는 것으로 표현하지 않습니다.
- 서점 구매 표시는 캐릭터 30+5=35하트, 소설 회차 10+2=12하트입니다.
- 소설은 완결 작품만 제목을 정해 전체 회차를 등록하고, 회차별로 판매합니다.
- 추가 컨셉 예시는 #3 뒤에 입력 → #4~#8의 새 5편으로 이어지는 흐름입니다.
- 하트 상품은 기존 기획의 100개 2,000원 / 250+50개 5,000원 / 500+200개 10,000원 / 비갱신 30일 패스 5,000원을 따릅니다.

## 대화·소설 화면의 생성 기능 보완

- **06 대화:** 입력창 위에 `장면 생성 · 30 ♥`와 `장소·의상 변경` 상태를 표시합니다. 장소 또는 의상 중 하나라도 실제로 바뀐 대화에서 활성화합니다. 미래의 이동 제안이나 회상은 변화로 처리하지 않습니다. 자동 생성·자동 차감하지 않고 버튼 → 확인 팝업 → 생성 순서입니다. 대화 1회 2하트와 별도입니다.
- **07 소설:** 직접 작성 중인 최신 회차 화면에는 `추가 컨셉 (선택)` 입력란, `다음 이야기 만들기 · 15 ♥`, `삽화 생성 · 50 ♥`를 표시합니다. 추가 컨셉은 숨겨진 메뉴가 아닌 다음 이야기 버튼 위에서 바로 입력합니다.
- 추가 컨셉이 비어 있으면 현재 계획을 이어가고, 입력하면 다음 회차부터 새 5편으로 다시 계획합니다. 예시 #3 뒤 입력 → #4~#8. 현재 원고나 누적 번호를 초기화하지 않습니다. 완결 이후에는 새 컨셉을 입력해 이어갈 수 있습니다.
- 삽화는 사용자가 별도로 요청할 때만 생성합니다. 다음 회차 생성 15하트에 삽화 비용 50하트를 자동으로 더하지 않습니다.
- **18 장면 생성 확인 / 19 삽화 생성 확인**을 추가해 대상 장면·회차와 차감 하트·예상 잔액을 각각 보여줍니다.
- 구매한 소설을 읽기만 하는 화면에는 작가용 추가 컨셉·다음 회차 생성 기능을 표시하지 않습니다. 이번 07 시안은 작가가 자신의 이야기를 이어 쓰는 화면입니다.

## 생성 및 후속 구현

### 배경 이미지·갤러리 반영

- **06 대화 / 07 소설:** 상단에 `배경`과 `갤러리` 메뉴를 나란히 둡니다. 하단 5개 탭은 그대로 유지하며 갤러리를 여섯 번째 전역 탭으로 추가하지 않습니다.
- 대화 장면과 소설 삽화는 **본문 뒤의 옅은 배경 이미지**입니다. 특히 소설 본문 중간의 액자형 삽화는 제거하고 원고가 연속으로 읽히도록 합니다. 프로필 아바타·목록 표지는 정상 색감을 유지합니다.
- 배경 농도 예시는 20%입니다. **이미지 레이어만** 옅게 처리하며 글자·말풍선·버튼은 흐려지지 않습니다. 글자 대비를 우선하고 배경은 고정된 보조 장면으로 사용합니다.
- **20 대화 배경 선택 / 21 소설 배경 선택:** 첫 카드에 `배경 없음`, 다음에 생성된 원본·대화 장면·소설 삽화 썸네일을 표시합니다. 선택 체크, 배경 농도, 적용 버튼을 둡니다. 선택용 썸네일은 식별하기 쉽도록 원본 색감입니다.
- 대화 배경과 소설 배경 선택은 독립적으로 유지합니다. `배경 없음`은 화면 표시만 끄며 생성 이미지나 갤러리 보관 자료를 삭제하지 않습니다.
- **22 이미지 갤러리:** 현재 캐릭터의 생성 이미지를 `전체 / 대화 장면 / 소설 삽화`로 확인합니다. 이미지 선택 → **23 전체화면 보기**로 이동합니다.
- 전체화면은 이미지를 **옅게 처리하지 않은 원본 색감**으로 표시하고, 잘림 없이 전체 구도를 볼 수 있게 맞춥니다. 닫기·저장·배경 적용을 제공하며 공통 계정 헤더와 하단 탭은 숨겨 이미지에 집중합니다.
- 갤러리가 대화에서 열렸다면 `대화 배경으로 적용`, 소설에서 열렸다면 `소설 배경으로 적용`합니다. 전체화면 예시는 대화에서 진입한 경우입니다. 단순 열람만으로 배경이 바뀌지는 않습니다.
- 이미 생성한 이미지의 선택·배경 해제·갤러리 열람에는 새로운 AI 호출이나 하트 차감이 없습니다. 새 장면 생성 30하트·새 삽화 생성 50하트는 기존 확인 절차를 유지합니다.
- 배경 선택은 표시 설정이며, 캐릭터의 실제 장소·의상 기억이나 소설 회차·공통 시간선을 바꾸지 않습니다.

내장 **image_gen**으로 기준 화면을 생성하고, 같은 이미지를 스타일 참조로 사용하여 각 화면을 별도로 생성했습니다. 앱의 OpenAI API 키를 사용한 CLI/API 호출은 하지 않았습니다. 최초 프롬프트는 `prompts.json`, 추가 컨셉·장면·삽화 기능 보완 프롬프트는 `feature-update-prompts.json`에 보관했습니다.

옅은 배경·배경 선택·갤러리·전체화면 보완 프롬프트는 `background-gallery-prompts.json`에 보관했습니다.

충돌하는 설명이 있다면 최신 `reading-loading-prompts.json` → `background-gallery-prompts.json` → `feature-update-prompts.json` → 최초 `prompts.json` 순으로 적용합니다. 이전 프롬프트의 본문 중간 삽화와 회차 선택 칩·하단 잔여 편수 예시는 현재 디자인에 적용하지 않습니다.

최신 07번은 상단 `#1 / #2 / #3` 선택 칩과 하단 `이야기 #3 · 완결까지 2편`을 제거했습니다. 현재 회차 제목을 남기고 좌우 스와이프와 작은 화살표로 이미 생성한 원고를 넘깁니다. 페이지 이동은 생성·하트 사용과 분리하며 ‘다음 이야기 만들기’만 최신 회차에서 새 원고를 생성합니다. 추가 컨셉·삽화 생성·배경·갤러리 기능은 유지합니다.

24번은 공통 생성 로딩 팝업입니다. 종이와 보라색 펜 일러스트, 활동 표시, 현재 단계, `생성 취소`를 제공합니다. 소설은 `이야기를 쓰고 있어요`, 캐릭터·대화 장면·소설 삽화 생성은 모두 `그림을 그리고 있어요`로 안내합니다. 표시용 일러스트는 번들 자산이며 매번 AI로 생성하지 않습니다. 총 24개 시안이며 확인 7개와 로딩 1개를 같은 팝업 필터에 모았습니다.

이 파일들과 이미지는 검토용 시안입니다. 최종 구현에서는 한글 문구·숫자·아이콘을 실제 UI 컴포넌트로 렌더링해야 하며 이미지의 작은 글자나 생성상의 오탈자를 그대로 제품 문구로 사용하지 않습니다. 위 표와 프롬프트의 텍스트가 문구·가격의 기준입니다.

이번 5개 탭·캐릭터 중심 목록·닉네임/하트 헤더·라벤더 톤을 실제 웹·Android 공유 UI에 적용했습니다. 시안 PNG를 화면으로 표시하는 방식이 아니라 실제 폼·탭·목록·팝업 컴포넌트를 사용합니다. 첫 로그인 프로필은 Supabase Auth 사용자 메타데이터에 저장하며, 실제 Google 로그인·결제 검증과 운영 재배포는 별도로 확인해야 합니다. 첫 로고 이미지는 사용자가 제공할 예정이므로 새 로고 이미지를 임의로 만들지 않았습니다.
