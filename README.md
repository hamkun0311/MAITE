# MAITE — 캐릭터 생성 · 대화 · 이야기

로그인 없이 2D 애니메이션 캐릭터를 만들고 대화와 이야기를 이어가는 사업성 검토용 MVP입니다. Next.js/Vercel에서 실행하며 별도 CAD/GPU 서버는 운영하지 않습니다. 기본 주소 `/`는 캐릭터 생성 화면 `/ideal`로 이동합니다. 상단에 모양 메뉴는 표시하지 않습니다.

## 개발 언어와 기술 스택

주 개발 언어는 **TypeScript**입니다. 화면은 React의 `.tsx` 컴포넌트로 작성하고, 서버 API와 소설·이미지·CAD 처리 로직은 `.ts`로 구현합니다. TypeScript의 `strict` 검사를 사용합니다. 스타일은 CSS, 설치·빌드 보조 스크립트는 JavaScript의 ES Modules(`.mjs`)를 사용합니다.

아래 버전은 `package.json`의 선언 기준입니다. 실제 설치 버전은 `package-lock.json`으로 고정하며 `npm ci`로 재현합니다.

| UI | React 19.2 | 캐릭터 생성·대화·이야기·이미지 갤러리 화면 |
| 서버 런타임 | Node.js | Route Handler 실행, OpenAI 호출, 이미지 변환 |
| 스타일 | Tailwind CSS 4, PostCSS, 전역 CSS | 반응형 화면과 모바일 읽기 영역 |
| 아이콘 | Lucide React | 대화·이야기 진입, 생성·설정 등 버튼 아이콘 |
| 데이터 검증 | Zod 4.3, JSON Schema | 요청·AI 구조화 응답·소설 기억·CAD 명세 검증 |

`scripts/verify-step.py`는 Python과 `cadquery-ocp-novtk`를 사용하는 **선택적 STEP 독립 검증 도구**입니다. Python 웹 서버는 운영하지 않으며, 캐릭터·대화·이야기 기능 실행에 Python 설치는 필요하지 않습니다. WebAssembly는 브라우저 CAD 엔진의 실행 형식이며, 프로젝트의 주 개발 언어는 TypeScript입니다.

## 코드 구조와 처리 방식

| 경로 | 담당 기능 |
|---|---|
| `app/ideal/` | 캐릭터 생성·대화·이야기 페이지와 공유 레이아웃 |
| `app/api/` | 서버 API: 캐릭터 이미지(`/api/characters`), 대화·소설(`/api/chat`), CAD 명세(`/api/generations`) |
| `components/` | React 화면, 실시간 응답 표시, 이미지 갤러리·배경·확대 보기 |
| `lib/chat/`, `lib/novel/` | 캐릭터 설정·말투·의상 감지, SSE 처리, 회차 설계·집필·검토·기억 갱신 |
| `lib/characters/` | 이미지 요청 검증, 그림체·장면·현재 장소 프롬프트 구성 |
| `lib/cad/`, `workers/cad.worker.ts` | CAD 명세 검증과 브라우저 Web Worker의 형상 생성·STEP 재검증 |
| `scripts/`, `public/wasm/` | CAD 실행 파일 준비 스크립트와 설치 시 복사되는 WASM 자원 |
| `tests/`, `tests/browser/` | 단위·API 테스트와 브라우저 E2E 테스트 |

브라우저는 React Context와 컴포넌트 상태로 캐릭터·대화·소설·갤러리를 관리하고, 서버 API에 필요한 문맥을 전달합니다. 서버는 OpenAI 키를 보관하고 입력 검증·콘텐츠 검사·모델 호출을 수행합니다. 대화는 SSE(`text/event-stream`)로 본문을 전달하고, 소설은 검증된 원고와 기억을 함께 확정하며, 이미지는 JPEG 바이너리로 반환합니다.

CAD의 무거운 연산은 서버가 아닌 브라우저 Web Worker에서 실행합니다. 캐릭터 기능은 현재 탭 메모리를 사용하고, 기존 판재 기술 검증 화면의 최근 작업은 `localStorage`를 사용합니다. 현재 MVP에는 로그인·서버 DB·영구 이미지 저장소를 연결하지 않았으며, Supabase 저장 기능은 향후 도입 대상으로 구분합니다.

## 실행

Node.js 22.18+ 또는 24 LTS를 사용합니다. `npm ci` 후 `.env.example`을 `.env.local`로 복사해 서버 환경변수를 설정하고 `npm run dev`를 실행합니다.

```env
OPENAI_API_KEY=OpenAI_서버_키
OPENAI_MODEL=gpt-6.1-sol
OPENAI_IMAGE_MODEL=gpt-image-2.5-sunburst
OPENAI_IMAGE_QUALITY=low
```

Vercel에도 같은 환경변수를 등록하고 재배포합니다. 키는 서버 전용이며 `NEXT_PUBLIC_*`에 넣지 않습니다. Cloudflare 설정, 접근 코드, Supabase 설정은 필요 없습니다. Supabase는 향후 저장 기능이 필요할 때 연결합니다. 캐릭터 이미지·입력 설정·대화·이야기는 `/ideal` 공통 레이아웃의 탭 메모리에 유지되어 세 화면 이동·브라우저 뒤로/앞으로 가기에도 보존됩니다. 새로고침이나 스튜디오 밖으로 이동하면 초기화됩니다. 캐릭터 없이 대화·이야기 주소에 직접 접속하면 생성 화면으로 안내하며 AI를 호출하지 않습니다. 응답 생성 중 다른 화면으로 이동하면 요청을 취소하고 미완료 응답은 다음 문맥에서 제외합니다.

## 기존 CAD 기술 검증 — `/technical/cad`

채팅 → OpenAI 프롬프트 정리 및 제한된 CAD 명세 → 브라우저 Worker의 OpenCascade.js → Three.js 미리보기 → STEP/JSON 다운로드.

- box / ellipsoid / cylinder / roof, 이동·회전·절삭, 최대 40개 부품을 지원합니다.
- 브라우저에서 실제 B-Rep을 만들고 STEP을 다시 읽어 유효성·치수를 검사합니다.
- STEP은 여러 솔리드의 조립체일 수 있습니다. 실사 피규어, 정밀 복제, 단일 융합 솔리드·즉시 출력 가능한 형상을 보장하지 않습니다.
- `/technical/plate`는 기존 판재 검증 화면입니다. 과거 구현 기록은 `docs/previous-implementation-notes.md`에 있습니다.
- WASM 약 23MB는 `postinstall`에서 준비합니다. 필요하면 `npm run prepare:cad`를 실행합니다.

## 캐릭터 생성 — `/ideal`

채팅 → OpenAI 콘텐츠 검사 및 캐릭터 설명 정리 → **GPT Image 2.5 Sunburst** → **세로형 9:16, 720×1280 JPG 다운로드**.

남녀 캐릭터의 톤앤매너를 `lib/characters/schema.ts`의 `CHARACTER_STYLES.female` / `CHARACTER_STYLES.male`에 각각 저장합니다. OpenAI가 대화의 요청 대상에 맞게 `styleProfile`을 선택하며 최신 성별 변경 요청을 우선합니다. 일반 수정은 이전 프로필을 이어갑니다. 성별 미지정·비인간 대상은 공통 스타일, 남녀가 함께 등장하면 혼합 스타일을 사용합니다. 머리 길이나 옷차림만으로 성별을 단정하지 않습니다.

- **여자 스타일:** 기존 모험가 샘플의 선명한 윤곽선, 풍부하고 따뜻한 채색, 셀 그림자와 부드러운 하이라이트, 장식의 정교한 마감을 참고합니다.
- **남자 스타일:** 새 첨부 샘플을 분석한 가늘고 섬세한 선화, 정제된 각진 얼굴 묘사, 저채도 회색·보랏빛 명암, 부드러운 셀 채색과 절제된 광택, 차분한 분위기를 참고합니다. 검은 머리·보라색 눈·귀걸이·초커·손짓을 자동으로 복제하지 않습니다.

결과 영역은 캐릭터 이미지만 바로 표시합니다. 그림체 참고·생성 프롬프트 탭과 샘플 이미지는 화면에 표시하지 않습니다. 실제 생성 스타일은 입력한 캐릭터 설정에 따라 자동으로 정합니다.

생성 이미지를 클릭하거나 키보드로 선택하면 화면 전체를 채우는 확대 보기 창을 엽니다. 이미지 비율을 유지해 전체 모습을 보여주며, 닫기 버튼·Esc·이미지 바깥 배경 클릭으로 닫습니다. 열려 있는 동안 배경 스크롤을 막고, 닫으면 원래 이미지 버튼으로 초점을 돌려줍니다.

인물·나이·성별·체형·의상·색상·표정·포즈·동반 생물·배경은 채팅 내용에 따라 정합니다. 샘플의 모험가·드래곤·의상을 자동으로 복제하지 않으며, 여성의 글래머러스함이나 남성의 섹시함도 자동 추가하지 않습니다. 2D 애니메이션 표현을 유지하고 모든 인물을 성인으로 고정하지 않습니다. 어린 캐릭터는 나이에 맞는 비성적인 디자인으로 표현합니다.

공통 스타일과 프롬프트 조립은 `lib/characters/schema.ts`에 있습니다. 입력으로부터 최대 800자의 ASCII 영문 subject를 정리해 스타일 지시와 결합합니다. 생성 프롬프트는 화면에 노출하지 않으며, 대화·이야기의 캐릭터 문맥에는 계속 반영합니다.

- 여자 스타일은 기존 샘플 PNG를 그림체 참고로 전달합니다. 남자·공통·혼합 스타일에는 여자 샘플 파일을 보내지 않습니다. 남자 스타일은 첨부 이미지를 분석한 저장 프롬프트로 적용합니다. 참고 파일이나 이전 결과가 없으면 Images generations, 있으면 Images edits를 사용합니다. 수정 시 직전 결과를 입력해 정체성과 변경하지 않은 디테일의 유지를 요청하며 완벽한 동일인 유지를 보장하지는 않습니다.
- API에 720×1280 생성 크기를 요청하고 세로형 9:16 구도를 지시합니다. sharp로 최종 720×1280 JPEG를 보장하며, 다른 비율의 응답에는 여백을 넣어 피사체를 자르지 않습니다. GPT Image에는 FLUX의 ‘4단계’ 옵션이 없습니다.
- 품질은 기존 저비용 선호에 따라 `low`가 기본이며 `OPENAI_IMAGE_QUALITY`로 변경할 수 있습니다. 프롬프트 정리와 이미지 생성에는 OpenAI 요금이 적용됩니다.
- multipart 요청 최대 약 2.65MB, 직전 JPEG 최대 2.5MB, 최대 13개 메시지, 인스턴스 전체 분당 3회로 제한합니다. 이는 분산 환경의 전역 비용 제한이 아닙니다.
- 결과는 binary JPEG로 반환합니다. 실패/취소 시 새 결과 다운로드를 비활성화하고, 취소한 입력은 복원합니다. 새 대화는 이전 이미지 참조까지 삭제합니다.
- 서버 요청은 최대 270초, Vercel 함수 설정은 300초이며 배포 플랜에서 허용해야 합니다. 참고 PNG를 함수에 포함하도록 파일 추적을 설정했습니다.

## 캐릭터 대화 · 이야기 만들기

캐릭터 특성의 성격 입력 위에 성별 선택박스를 두고 남성·여성·바이섹슈얼 중 하나를 선택합니다. 선택은 새 캐릭터 생성 폼의 필수 항목이고, 수정·화면 이동 시 유지하며 전체 초기화 시 비웁니다. 생성 시 확정한 값은 이미지·대화·소설에 함께 전달됩니다. 기존 탭/API 프로필에 선택값이 없는 경우도 호환합니다. 바이섹슈얼은 지향을 뜻하므로 이를 근거로 외형·신체 성별·성격·호감 대상을 임의로 정하지 않고 컨셉과 명시된 외형을 따르도록 지시합니다.

이상형 화면에서 **캐릭터 이름·나이·성별·성격·컨셉 입력 → 캐릭터 생성 → 이미지 하단 아이콘 선택** 순서로 사용합니다. 장르 선택박스는 없으며 이미지·대화·이야기는 모두 막장드라마로 고정합니다. `lib/chat/character.ts`의 `FIXED_CHARACTER_GENRE`를 사용하고, 이전 탭이나 API 요청의 기존 장르 값도 서버 검증에서 막장드라마로 정규화합니다. 별도 키워드 입력 없이 특성과 컨셉으로 이미지를 만들며 수정도 같은 버튼으로 생성합니다.

생성(`/ideal`)·대화(`/ideal/chat`)·이야기(`/ideal/story`)는 독립된 페이지입니다. 각 페이지는 자신의 화면만 렌더링하고 공통 레이아웃이 캐릭터와 기록을 유지합니다. 상단의 이미지·대화·이야기 선택 메뉴는 표시하지 않습니다. 생성 이미지 바로 아래의 말풍선·책 정사각형 아이콘 버튼으로 대화·이야기 페이지로 이동합니다. 아이콘은 접근성 이름과 툴팁으로 구분합니다. 각 화면의 뒤로 버튼으로 이미지 결과로 돌아갈 수 있으며 브라우저 뒤로/앞으로 가기도 지원합니다. 대화·이야기는 생성 시 확정한 특성과 장르를 공유하고, 이야기 페이지에 처음 진입하면 첫 장면을 작성합니다. 막장드라마의 갈등·비밀·반전과 캐릭터 컨셉을 역할 지시에 반영합니다. 대화·이야기 상단의 캐릭터 정보에는 이름·나이만 표시하고 장르 문구는 숨깁니다. 모바일에서 생성 완료 시 이미지 결과로 스크롤합니다. 각 화면의 배경에 생성 이미지를 사용하고 글 영역에는 반투명 패널을 적용합니다.

`gpt-5.4-mini`의 Responses API 스트리밍으로 답변을 표시합니다. 마지막 성공 이미지의 생성 요청(후속 수정 포함), 요약, 생성 프롬프트와 입력한 캐릭터 설정을 매 요청에 전달합니다. 실제 이미지 픽셀을 모델에 보내지는 않습니다. 대화는 캐릭터의 1인칭 말투와 감정·관계를 유지하며 캐릭터가 사용자에게 직접 하는 말만 출력합니다. 강한 컨셉·막장드라마 분위기도 말의 내용과 어조에 반영하고 배경·날씨·행동·내면 서술·괄호 지문·사용자의 답변 대필은 넣지 않도록 합니다. 이야기는 별도로 서술과 대사가 있는 연재 소설로 이어집니다. 설렘·라이벌·비밀·갈등·반전 등을 활용하되 노골적인 성적 묘사는 피하고, 미성년 캐릭터는 나이에 맞는 비성적 콘텐츠로 제한하도록 지시합니다. 화면에 AI가 만드는 허구의 대화·이야기임을 표시합니다.

대화의 존댓말·반말은 컨셉과 관계를 기준으로 시작하고, 사용자에게 하는 말 전체에서 한 어투를 유지하도록 지시합니다. ‘반말해줘’, ‘존댓말로 말해주세요’처럼 명확한 요청은 즉시 반영하고, 간접적인 요청·관계 변화는 현재 어투와 완료된 대화 문맥을 함께 판단합니다. 사용자의 짧은 반말·존댓말 한마디만 따라 무작위로 전환하지 않도록 합니다. 선택된 어투는 성공적으로 끝난 답변과 함께 탭 메모리에 저장하므로 최근 20개 메시지 밖으로 전환 요청이 밀려나거나 이미지 화면으로 갔다 돌아와도 유지됩니다. 실패·취소된 답변은 어투를 바꾸지 않으며 새 대화·캐릭터 변경은 초기화합니다. 문맥 판단에는 같은 모델로 최대 500토큰의 추가 호출 1회가 필요하고, 명확한 전환 요청은 이 호출을 생략합니다. 본문은 계속 스트리밍하며 모델 지시를 사용하므로 모든 표현의 완벽한 일관성을 보장하지는 않습니다.

대화와 이야기의 기록은 서로 분리되며 화면을 오가도 유지됩니다. 각 화면의 ‘캐릭터 설정’은 공통 특성 입력으로 돌아갑니다. 특성 수정은 이미지를 다시 생성해야 대화·이야기에 적용되며, 입력 중에는 기존 기록과 확정한 특성을 유지합니다. 새 이미지 생성·수정은 양쪽 기록을 초기화하고, 상단 새 대화는 특성 입력·이미지·참조까지 초기화합니다. 각 화면의 새 대화는 해당 기록만 초기화합니다. 대화 메시지로 이미지를 자동 생성·수정하지는 않습니다.

대화·이야기는 화면 높이에 맞춘 읽기 화면을 사용합니다. 제목·캐릭터 정보는 한 줄 영역으로 모으고, 대화 입력창은 작게 유지해 본문에 공간을 우선 배분합니다. 이야기 화면에는 메시지 입력창 없이 ‘삽화 보기’와 그 아래의 ‘다음 이야기’ 버튼을 배치합니다. 처음 진입하면 첫 장면을 작성하고, 이후 버튼을 누르면 완료된 이전 줄거리·인물 관계·캐릭터 설정·장르를 이어서 다음 장면을 작성합니다. 생성 중에는 버튼을 비활성화하고 실패하면 다시 누를 수 있습니다. 초기화 후에는 같은 버튼으로 첫 장면부터 시작합니다. 자동 요청 문구는 본문에 표시하지 않습니다. 이야기 영역의 머리말은 ‘함께 쓰는 이야기’ 제목만 표시하며 별도 안내 문구를 넣지 않습니다. 대화 본문은 16px, 이야기 본문은 17px와 넓은 행간으로 표시합니다. 모바일 키보드나 창 크기 변경 시 보이는 높이에 맞춰 조정합니다. 이야기는 새 회차의 첫 줄부터 읽으며 생성 중 아래로 강제 스크롤하지 않습니다. 대화도 위쪽 기록을 읽는 동안에는 새 응답이 와도 위치를 유지합니다.

대화 화면은 뒤로 가기·제목·캐릭터 정보·설정·새 대화를 하나의 상단 바로 합쳐 본문 높이를 더 확보합니다. 좌우 여백과 입력창도 줄이고, 데스크톱에서는 이전 1,100px 너비 제한을 해제해 채팅 영역을 넓힙니다.

대화·이야기는 Markdown 강조·행동 표시 기호를 쓰지 않도록 지시합니다. 캐릭터 대화는 Structured Outputs의 utterances 배열(1~3개, 각 최대 2,000자)로 생성하며 서버가 그 문자열 값만 추출해 스트리밍합니다. JSON 구조나 다른 서술 필드는 전달하지 않으며, 전체 응답이 끝날 때 스키마를 검증합니다. 이 과정에 별도 편집 모델 호출을 추가하지 않습니다. 대화에는 분위기와 성격에 맞는 이모지·ㅋㅋ·ㅎㅎ·ㅠㅠ·^_^·:) 등을 가볍게 허용하며, 보통 0~2개 정도로 과용하지 않도록 하고 사용자의 거부 요청을 존중합니다. 대화 표시와 다음 대화 문맥에서도 이모지·이모티콘을 유지합니다. 소설은 기존 문장·문단 서술과 기호 정리, 이모지 금지를 유지합니다. 대화의 대기 문구는 ‘대화 작성중’입니다.

이야기의 ‘삽화 보기’는 가장 최근 완료된 원고와 누적 요약·현재 상황을 구분해 원본 캐릭터 이미지와 함께 전달합니다. 원본은 얼굴·나이·머리카락·눈 등 인물 식별에 사용하고, 최신 회차의 한 장면에 맞춰 자세·손짓·표정·의상·소품·상호작용·구도를 새로 구성하도록 지시합니다. 이 지시는 프롬프트 정리와 최종 이미지 생성 양쪽에 전달하며, 배경만 바꾸거나 원본의 서 있는 자세를 복제하지 않도록 합니다. 명시된 의상 연속성은 유지합니다. 삽화는 최신 원고에서 현재 장소를 먼저 확인하고, 그 회차에 장소가 생략되면 요약·현재 상황으로 이어지는 장소를 확인합니다. 회상·이전 장면·다른 인물의 위치·미래 목적지는 현재 장소보다 우선하지 않습니다. 삽화 설명은 별도 필수 필드 sceneLocation(ASCII 영어 최대 300자)과 locationSource로 장소를 정리하며, 서버가 이를 최종 이미지 요청의 REQUIRED CURRENT SCENE LOCATION에 명시합니다. 따라서 800자 인물 설명에서 장소가 빠져 원본 배경으로 돌아가지 않도록 합니다. 현재 장소를 알아볼 수 있는 환경과 구도를 요구하며, 카페라면 원래 방에 커피잔만 더하지 않고 카페 좌석·카운터 등 식별 가능한 요소를 표현하도록 합니다. 대화는 유카타·기모노·치파오 등 의상 이름만 있어도 ‘의상 변경하기’를 표시합니다. 알려진 단어는 즉시 감지하고, 목록에 없는 의상은 마지막 사용자 메시지와 완료된 응답을 같은 모델로 최대 350토큰의 추가 호출 1회로 판별합니다. 의상 변경 버튼은 마지막으로 완료된 사용자 메시지와 캐릭터 답변 한 차례를 기준으로 활성화합니다. 최근 대화에 의상 언급이 없으면 과거에 의상 이야기를 했더라도 버튼을 비활성화하고, 다시 언급되면 활성화합니다. 의미 판별 결과가 없으면 해당 최근 두 메시지의 의상 단어만 확인하며 더 오래된 대화로 활성화하지 않습니다. 실패·중단된 응답은 최근 판별을 바꾸지 않습니다. 화면 이동 시 상태를 유지하고 새 대화에서 비우며, 판별 실패만으로 완료된 대화 본문을 버리지는 않습니다. 텍스트·이미지 생성 중에는 중복 이미지 요청을 막으며 실패·취소·지연 결과 차단과 갤러리 동작은 유지합니다.

두 화면 상단의 ‘배경 변경’에서 현재 캐릭터의 원본·의상 변경 이미지·이야기 삽화를 함께 볼 수 있습니다. 선택한 배경은 대화와 이야기별로 유지되며, 이미지를 고르는 동작은 AI를 호출하지 않습니다. 이미지 생성은 기존 서버 키·모델·검사·요청 제한을 공유하고 프롬프트 정리 및 이미지 생성 요금이 적용됩니다. 이미지 생성용 장면 문맥은 최대 12,000자, 캐릭터별 이미지 보관은 원본 포함 최대 24장입니다. 이미지는 현재 탭 메모리에서만 유지하며, 캐릭터 새 생성·수정 또는 상단 새 대화는 이미지 목록과 선택 배경을 초기화합니다. Blob URL은 초기화·스튜디오 종료 시 해제합니다. 캐릭터 정체성 유지는 원본 이미지를 참고하도록 요청하며 실제 생성 품질과 완벽한 동일인 유지를 보장하지 않습니다.

- 기존 `OPENAI_API_KEY`만 사용하며 별도 키나 모델 설정은 필요 없습니다. 이미지 생성 모델 설정과 독립적입니다. 대화에는 OpenAI 사용 요금이 적용됩니다.
- Enter로 보내기, Shift+Enter 줄바꿈, 응답 중지, AI 대화 초기화를 지원합니다. 완료된 대화를 다음 요청의 문맥에 반영하며 중단된 답변은 문맥에서 제외합니다.
- `/api/chat`은 `stream:true`, `store:false`로 호출합니다. 서버가 SSE를 해석해 답변 텍스트·완료·오류만 브라우저에 전달하고, 연결 종료 시 외부 생성 요청도 취소합니다. 키나 외부 오류 세부정보는 노출하지 않습니다.
- 최근 최대 21개 메시지, 총 24,000자, 캐릭터 이미지 설명 최대 6,000자, 이름 80자, 성격·컨셉 각각 1,000자, 나이 정수 1~120세, 요청 전체 100KB, 출력 최대 2,000토큰, 서버 타임아웃 150초, 인스턴스별 분당 15회로 제한합니다. 대화는 현재 탭 메모리에만 유지됩니다.
- [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [OpenAI 스트리밍 문서](https://developers.openai.com/api/docs/guides/streaming-responses).

의상 변경의 배경은 대화에서 확인된 현재 실제 장소를 우선합니다. 작업실을 떠나 백화점 의류 매장에 도착했다면 새 의상과 함께 백화점·피팅 공간을 표현하도록 프롬프트 정리와 최종 이미지 요청 양쪽에 지시합니다. 원본 이미지는 인물 식별용이며 배경을 고정하지 않습니다. 앞으로 갈 장소·회상·가정·다른 인물의 위치는 현재 장소로 취급하지 않고, 현재 장소나 이동이 확인되지 않으면 기존 배경을 유지합니다. 고정 응답 테스트로 현재 장소 전달과 양쪽 프롬프트의 우선순위 지시를 확인합니다.

### 소설 전개 개선

루트 `novel_mvp_improvement_guide.md`를 반영해 소설을 회차 설계 → 집필 → 전개 검증 → 기억 갱신 순서로 생성합니다. `lib/novel/generate.ts`가 3~5개의 인과적인 장면, 새 정보, 주인공의 선택과 결과를 먼저 설계합니다. 매번 같은 위협이나 미해결 질문으로 끝내는 지시를 없애고, 장르에 맞는 작은 성취와 실제 상황·관계 변화를 요구합니다. 장르는 막장드라마로 고정하되 캐릭터의 동기와 사건의 인과관계를 유지합니다.

`lib/novel/state.ts`의 회차 기억에는 요약, 장기 목표, 현재 상황, 최근·해결된 사건, 미해결 갈등, 세계의 사실, 인물별 지식·관계, 직전 결말, 다음 회차 목표를 따로 보관합니다. 집필에는 과거 원고 전체 대신 이 기억과 설계를 전달하고, 직전 원고는 검토 단계에서만 비교합니다. 검토·기억 추출은 역할극 지시에서 분리한 편집자 지시를 사용합니다. 원고를 최대 360자의 근거 문장으로 나누고, 모델의 evidence 필드는 실제 문장의 ID 목록 중에서만 선택하도록 Structured Outputs로 제한합니다. 서버가 선택된 ID를 원문으로 복원하므로 모델이 인용문을 바꿔 쓰거나 번역해 정상 원고가 탈락하는 문제를 피합니다. 없는 ID는 거부하며 근거가 있는 차단 사유나 직전 원고의 상당 부분 복사가 발견되면 최대 한 번만 재작성합니다. 불완전 응답·검토 실패·기억 추출 실패는 성공으로 반영하지 않습니다. 기억 패치는 기존 기억에 병합합니다. 원문 참조 확인은 선택한 문장이 주장을 뒷받침하는지까지 완벽히 보증하지 않으며 실제 연속성·재미는 별도 평가가 필요합니다.

전개 검증은 계획한 장면 수의 완전 일치를 요구하지 않습니다. 실제 새 사건과 결말 변화의 원문 근거가 있고 심각한 반복·설정 충돌·인과 단절·진행 정체가 없으면, 일부 장면이 다음 화로 넘어가거나 missing_beat 지적만 있어도 채택합니다. 그 외 실질적인 문제는 여전히 최대 한 번 재작성하고 실패 시 기존 회차를 유지합니다. 검토 진단은 원고 없이 메타데이터만 JSON 문자열로 남깁니다.

원고와 기억은 모든 단계 및 완료 신호가 성공한 뒤 함께 반영합니다. 실패·화면 이동·취소는 이전 회차와 기억을 유지합니다. 화면은 진행 상태를 표시하며 미검토 초안은 노출하지 않습니다. 새 대화·캐릭터 변경 시 기억도 초기화합니다. DB나 서버 로컬 파일을 추가하지 않으며 현재 탭 메모리만 사용하므로 새로고침하면 사라집니다. 회차 기억은 최대 16,000자이며 목록별 상한과 전체 예산을 넘으면 오래된 세부 항목부터 제거하고 누적 요약·직전 결말을 유지합니다. 무제한 장기 기억을 보장하지 않습니다.

모델은 기존 `gpt-5.4-mini`를 유지합니다. 소설 한 회차는 기본 4회 호출, 재작성 시 최대 6회 호출하며 각 내부 단계는 최대 2,400토큰, 집필은 최대 3,000토큰입니다. 전체 서버 제한은 150초이고 인스턴스별 분당 15회 제한은 사용자 요청 단위입니다. 캐릭터 대화는 어투 선택·의상 판별을 포함해 최대 3회 호출이며 본문 2,000토큰 스트리밍은 유지됩니다. 호출 증가로 비용·지연이 늘어날 수 있습니다. 로그에는 프롬프트 버전·모델·회차·기억 유무·문맥 길이, 실패 단계·정해진 오류 분류·검토 통과 여부·계획/완료 장면 수·문제 유형만 남기고 원고·프로필·키는 남기지 않습니다.

고정 응답 테스트는 기억 병합·원문 참조·전개 검증·재작성 상한·근거 없는 수정 차단·실패 시 미반영·모바일 읽기와 삽화 연결, 대화 어투의 유지·전환·실패·초기화를 확인합니다. 2026-11-15 실제 API로 한국어 첫 회차와 2회차 생성 완료, 존댓말 → 반말 → 반말 유지 → 존댓말의 4턴 전환을 확인했습니다. 이는 제한된 기능 확인이며 실제 모델의 장기 반복률·재미·장르별 품질·지연을 비교 평가한 것은 아닙니다. 실제 원고로 기존 방식과 비교 평가하는 것이 다음 품질 검증 작업입니다.

2026-11-15 실제 이미지 API로 원본의 모험가 의상·용을 안은 자세를 남색 유카타·무릎을 꿇고 편지를 읽는 자세로 바꾼 삽화를 생성하고 확인했습니다. 결과는 `.verification/scene-illustration-live.jpg`의 720×1280 JPEG입니다. 실제 API의 목록 밖 의상 ‘키톤’ 감지도 확인했습니다. 이는 단일 장면 확인이며 모든 장면의 인물 동일성이나 표현 품질을 보장하지는 않습니다.

의상 변경도 실제 API로 기존 실내·유카타 참조를 백화점 피팅룸·하늘색 재킷·검은 슬랙스로 바꾸는 사례를 생성해 확인했습니다. 결과는 `.verification/outfit-current-location-live.jpg`입니다. 대화에는 이후 카페로 갈 계획도 포함했으며 현재 장소인 피팅룸이 반영됐습니다. 단일 사례 확인으로 모든 장소·구도의 정확성을 보장하지는 않습니다.

삽화의 현재 장소도 실제 API로 확인했습니다. 원본이 실내 작업 공간인 이미지를 참조하고 최신 원고에는 작업실 회상·향후 백화점 방문을 섞되 현재 상황은 카페로 전달했습니다. 별도 장소 필드가 카페를 선택했고, 최종 이미지에 카페 좌석·테이블·커피·디저트 진열 공간이 반영됐습니다. 검증용 결과는 `.verification/illustration-current-cafe-live.jpg`이며, 단일 사례 확인과 일반적인 장기 품질 검증은 구분합니다.

2026-11-15 실제 대화 API로 배경 묘사가 강한 컨셉과 남성·여성·바이섹슈얼 프로필 각각에서 직접 대화·반말·이모지/이모티콘 출력을 확인했습니다. 이는 제한된 사례이며 모든 컨셉의 서술 배제나 말투 일관성을 보장하는 장기 평가는 아닙니다. 고정 응답 테스트는 JSON 스트림 경계·유니코드 이스케이프·이모지·스키마 실패 처리와 선택값의 화면 이동·전달·초기화를 확인합니다.

## 검증

변경 후 다음 명령을 순서대로 실행합니다.

```sh
npm run typecheck
npm test
npm run test:e2e
npm run build
```

E2E는 Chromium이 필요합니다(`npx playwright install chromium`). 포트 3100과 `.next-test`를 사용하며 `PLAYWRIGHT_PORT`로 변경할 수 있습니다. Next.js 생성 타입 파일을 공유하므로 build와 동시에 실행하지 않습니다.

- API 테스트는 외부 응답만 고정해 모델·생성 크기·품질·참고 이미지 순서, 이전 결과 전달, 입력 제한·콘텐츠 차단·요청 제한 및 실제 sharp 변환 결과의 720×1280 JPEG를 검증합니다.
- 브라우저 테스트는 메뉴·참고/프롬프트 탭 제거·생성 이미지 표시·수정·다운로드·취소·모바일과 기존 CAD Worker/STEP 흐름을 검증합니다.
- AI 대화 테스트는 UTF-8/청크 경계 처리, 완료 전 텍스트 전달, 문맥 유지, 입력 제한, 외부 요청 취소, 중지·실패 후 재시도 및 이미지 생성과의 분리를 검증합니다. 캐릭터 설정 검증과 이미지 콘텐츠 검사·생성 및 모드별 서버 지시 전달, 모바일 특성 입력·결과·메시지 입력창의 뷰포트 노출, 배경 이미지·특성 공유, 대화·이야기의 기록 분리, 메뉴 전환·설정 화면 복귀·전체 초기화도 검증합니다. API 응답은 고정하며 실제 유료 모델의 역할 유지·소설 품질·지연 시간은 별도 확인 대상입니다.
- 삽화·의상 변경은 원본 이미지와 현재 문맥 전달, 별도 역할 지시·문맥 크기·입력 검증, 완료된 텍스트의 기호 제거, 의상 버튼 표시, 이미지 공유 목록과 화면별 배경 선택, 생성 실패·취소·초기화 후 지연 응답 차단 및 Blob URL 해제를 고정 응답으로 검증합니다. 실제 유료 이미지 생성과 장면·의상·인물 반영 품질은 별도 확인 대상입니다.
- 다양한 실제 입력의 최종 그림체·프롬프트 반영 품질, Vercel 배포, FreeCAD GUI 수동 검증은 별도 확인 대상입니다. 고정 응답 테스트를 실제 생성 품질의 증거로 기록하지 않습니다.
