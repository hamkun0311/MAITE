# MAITE — 캐릭터 생성 · 대화 · 이야기

채팅은 정상 완료된 대사와 부가 기억의 검증을 분리합니다. 부가 패치가 잘못된 경우 기존 기억을 유지하고 대사는 완료하며, 실제 응답 절단/본문 오류는 계속 실패 처리합니다. 내부 진단에는 원문 대신 제한된 오류 사유만 기록합니다.

소설 생성은 기본 `reviewed`에서 독립 검수를 유지하며 공유 사건/원고 출처의 반복 필드명과 폐기할 기억 생성을 줄입니다. `OPENAI_NOVEL_GENERATION_MODE=integrated`로 신규 구간2회·기존 구간1회 호출의 실험 경로를 선택할 수 있습니다. 단일 호출의 실제 품질 동등성은 미검증이며 기본값으로 활성화하지 않았습니다. [설정·호출 수·검증 및 비교 방법](docs/NOVEL_PERFORMANCE.md)을 확인하세요.

캐릭터의 성격에서 파생한 동기·말버릇과 근거 있는 감정 상태를 캐릭터별로 저장하고, 채팅과 소설이 중요한 사건·관계를 출처와 지식 범위에 따라 공유합니다. 기존 UI와 클릭당 한 회차 생성은 유지합니다. 추가 모델 호출이나 DB 마이그레이션은 없으며, 기존 JSON 스냅샷의 선택 필드를 확장했습니다. [분석·구현 범위·검증 한계](docs/CHAT_NOVEL_CONTINUITY.md)를 확인하세요.

안부는 캐릭터마다 한국시간 하루 1회 예약하며, 해당 캐릭터에게 답장하기 전에는 반복하지 않습니다. 현재 대기 시간은 테스트용 3분이고 야간 제한은 22:00~10:00입니다. 읽지 않은 안부는 푸터 캐릭터 탭의 알림 점과 캐릭터 이름 옆 `안부 도착`으로 표시하며, 해당 대화 화면을 열어 확인하면 읽음 처리합니다. 읽음 상태는 DB에 저장합니다. `supabase/migrations/202611190001_character_checkin_inbox.sql`을 기존 003 마이그레이션 이후 적용해야 합니다. 기존 안부 기록과 잔액은 유지합니다. Android는 캐릭터별 로컬 알림을 예약하고, 웹은 열린 화면에서 확인합니다. 추가 AI 호출이나 하트 차감은 없습니다.

안부 변경 검증: 단위141개·관련 계정 화면5개·전체 웹39개·모바일 화면1개와 Next 빌드 통과. 로컬 DB에서 마이그레이션과 읽음 보존을 확인했습니다. Android 셸에도 로컬 알림 플러그인을 연결하고 Debug APK 빌드까지 확인했으며, 연결된 원격 DB의 읽음 컬럼·캐릭터별 최신 기록 RPC·읽지 않은 안부 조회도 성공했습니다. 실제 기기 알림은 별도 확인이 필요합니다.

이미지는 비공개 Supabase Storage에 저장합니다. 목록·갤러리는 256px WebP 썸네일, 전체화면과 배경은 원본을 사용하며 서명 URL 재사용과 계정별 메모리 캐시로 중복 전송을 줄입니다. 썸네일 생성에는 추가 AI 호출이 없습니다. 다른 Supabase 환경에는 `supabase/migrations/202611180002_storage_thumbnails.sql`도 적용하세요.

2D 애니메이션 캐릭터를 만들고 대화와 이야기를 이어가는 앱입니다. Next.js/Vercel에서 실행하며 별도 CAD/GPU 서버는 운영하지 않습니다. 기본 주소 `/`는 `/ideal`로 이동하며 계정 모드에서는 캐릭터 목록, 무인증 개발 모드에서는 캐릭터 생성 화면을 표시합니다. 상단에 모양 메뉴는 표시하지 않습니다.

Android 하이브리드 셸과 선택적 Google 로그인·Supabase 저장·하트·스토어 기능을 추가했습니다. 기본은 기존 개발 모드이며, 외부 설정과 계정 모드 활성화가 필요합니다. [설정·실행 및 남은 검증](docs/ANDROID_ACCOUNT_SETUP.md)을 확인하세요. `npm run mobile:dev`로 브라우저 미리보기, `npm run mobile:sync`와 `npm run mobile:open`으로 Android 프로젝트를 준비합니다. 실제 결제·광고와 공개 유료 운영 검증은 아직 완료하지 않았습니다.

계정 모드에서는 Google 로그인 후 최초 한 번 닉네임·성별·나이를 입력하고 캐릭터 목록으로 이동합니다. 하단은 **캐릭터·뉴페이스·서점·스토어·마이페이지** 5개 메뉴이며, 닉네임과 실제 보유 하트를 상단에 표시합니다. `app/native.css`가 웹·Android 공통 화면에 화이트·라벤더·보라색 모바일 디자인을 적용합니다. 뉴페이스는 캐릭터 생성, 서점은 작품 거래, 스토어는 하트 충전이며 마이페이지는 계정·프로필·하트 정보입니다. 대화·소설 목록은 캐릭터 상세 안에서 확인합니다. 프로필 수정은 현재 캐릭터를 잃지 않도록 모달로 엽니다. 프로필은 검증 후 본인의 Supabase Auth 사용자 메타데이터에 저장하며 DB 테이블 마이그레이션은 없습니다.

캐릭터 상세에서 불러오기와 판매 등록을, 소설 상세에서 회차별 읽기와 제목을 지정한 판매 등록을 제공합니다. 생성·구매·판매 전 확인 팝업에서 비용과 수수료를 보여주고, 취소하면 실행 API를 호출하지 않습니다. **서버에서 완결이 확인되고 전체 회차가 저장된 소설만 판매**할 수 있습니다. 소설은 작품 제목 아래 회차별 상품으로 등록하며 가격은 회차당 구매 10+수수료2 / 판매 10-수수료2하트입니다. 새 이야기를 시작해도 이전 소설의 독립 저장 항목은 남습니다. 공개 판매에는 원고만 복사하며 비공개 대화·설정 기억은 포함하지 않습니다.

기존 캐릭터 통합 저장 항목의 이야기도 캐릭터 상세에서 열 수 있습니다. 성공 후 하트 차감·삭제 기능에는 아래의 추가 DB 마이그레이션이 필요합니다. 실제 완결 생성 기록이나 전체 원고가 없는 항목은 판매할 수 없습니다. 계정 앱 화면 회귀 검사는 `npm run test:accounts`로 실행하며 가짜 세션과 모킹 API를 사용합니다. 기존 `npm run test:e2e` 및 `npm run build`와 순서대로 실행하세요. 운영에는 프로필 저장 API를 포함한 Next 서버를 먼저 배포한 뒤 Android 설치본을 동기화·재빌드합니다.

완결 작품 정보가 없는 기존 단일 회차 상품은 새 판매 목록에서 제외하고 신규 구매를 차단합니다. 판매자와 기존 구매자의 열람 권한은 유지합니다. 검증 명령은 `npm run typecheck`, `npm test`, `npm run test:e2e`, `npm run test:accounts`, `npm run test:mobile`, `npm run build`, `npm run mobile:sync`입니다. 자동 검증은 실제 Google OAuth·유료 구매·OpenAI 호출을 실행하지 않습니다.

## 현재 회차 삽화와 사용자 호칭

화면 진입 지연 개선: 같은 로그인 세션의 중복 GET을 공유하고 문서·이미지 주소를 함께 받습니다. 캐릭터 원본을 먼저 연 뒤 갤러리를 백그라운드에서 복원하며, 소설 상세는 이미지 조회 없이 원고만 읽습니다. 스토어 쿼리는 병렬 처리하고 짧게 캐시하며 변경 요청·로그아웃·명시적 새로고침 시 무효화합니다. 잔액 완료값과 사용자 간 데이터는 공유 캐시하지 않습니다. `Server-Timing` 응답 헤더로 인증·DB·이미지 서명 시간을 확인할 수 있습니다.

`npm run dev`는 Turbopack을 사용하며 기존 방식은 `npm run dev:webpack`으로 실행합니다. 배포 빌드는 기존 Webpack을 유지합니다. 하트 정산·소유권 검사·모델 생성 및 검토 횟수는 변경하지 않습니다.

삽화는 선택한 회차의 실제 등장인물·장소·시점을 기준으로 만듭니다. 기존 설명 정리 단계에서 원본 캐릭터의 등장 여부를 판단하고, 등장하지 않으면 렌더러에 원본 캐릭터 이미지를 보내지 않습니다. 다른 등장인물이나 풍경만 그릴 수 있으며 추가 AI 호출은 없습니다.

새 대화·소설의 사용자 호칭은 **컨셉에 명시한 자기 이름·호칭 > 사용자 닉네임 > 당신** 순으로 반영합니다. 내부 사용자 ID와 다른 등장인물의 이름은 유지하며 기존 원고는 자동으로 수정하지 않습니다.

소설 헤더의 새 이야기·캐릭터 설정 아이콘은 제거하고 배경 버튼에 이미지 아이콘을 넣었습니다. 하트 작업 내역 팝업 대신 상단 하트가 충전 스토어로 연결됩니다. 프로필 수정과 캐릭터 삭제도 앱 버튼 디자인을 사용합니다.

자동 저장은 짧은 시간의 변경을 합치고 이미 저장한 내용은 다시 보내지 않습니다. 성공 후 보관함 목록을 로컬 갱신하여 저장마다 계정 전체를 조회하던 흐름을 제거했습니다. 변경 없는 메뉴 이동에는 추가 저장·계정 조회가 없으며, 문서·이미지 조회의 불필요한 정산 대기와 사용하지 않는 조회 쿼리 3개도 제거했습니다. 생성 품질·검토 횟수는 유지하며 외부 모델 응답과 네트워크 지연은 남습니다.

## 성공 후 하트 차감과 캐릭터 삭제

`202611180001_deferred_billing_and_character_delete.sql` 적용 후 생성 중에는 사용 가능 하트·무료 대화만 예약합니다. 표시 잔액은 유지하며 유효한 완성 결과를 서버에 저장할 때 한 번만 차감합니다. 완료 확정 전 실패·취소는 예약만 해제합니다. 완료 저장 후 통신이 끊겨도 서버의 결과와 정산 기록은 보존됩니다. 하트 작업 내역 화면은 제거했습니다. 연결된 Supabase에는 해당 마이그레이션 적용을 확인했습니다.

캐릭터 상세 하단의 **캐릭터 삭제**에서 확인 후 개인 캐릭터와 연결된 소설을 보관함에서 제거하고 판매를 중지합니다. 기존 구매자의 사본·주문·정산 원장·완료 작업은 보존합니다. 상단 헤더에는 닉네임과 하트만 표시하며 읽기 화면의 배경 선택·갤러리는 유지합니다.

## 이야기 설정 반영

소설은 한 회차씩 읽으며 좌우 스와이프, 화살표 버튼 또는 키보드 방향키로 생성된 회차를 넘깁니다. 상단 회차 칩과 하단 남은 편수 문구는 제거했습니다. 회차 이동에는 API 호출이나 하트 사용이 없으며, ‘다음 이야기’는 최신 회차부터 이어 쓰고 성공한 새 원고를 표시합니다. 이전 회차의 삽화 생성은 선택한 회차를 기준으로 합니다. 보관함의 소설 상세도 스와이프로 읽을 수 있습니다.

소설 생성에는 종이와 펜 일러스트가 있는 취소 가능한 로딩 팝업을 표시합니다. 이미지 생성은 버튼의 스피너와 ‘그림을 그리고 있어요’ 문구로 표시하며 생성 중에도 본문을 읽고 기존 소설 회차를 넘길 수 있습니다. 이미지 완료 후 전체화면을 자동으로 열지 않습니다. 로딩 이미지는 앱에 포함되므로 표시할 때 AI를 호출하지 않습니다. 이미지 생성에는 손·팔의 윤곽이 덜 겹치도록 구도를 조절하는 지시를 추가했으며 별도 검증 호출이나 자동 재생성은 추가하지 않았습니다. 이 지시만으로 손 오류가 완전히 사라지지는 않습니다.

이야기 생성은 **중간 추가 설정 > 캐릭터 컨셉 > 막장드라마 강조** 순으로 반영합니다. 지정한 관계·사건·결말을 기존 AI 계획보다 우선하며, 막장 소재에는 비밀·음모·반전과 함께 치정도 포함합니다. 컨셉에 맞지 않는 추리 전개나 임의의 결말 변경은 피하도록 지시합니다.

기존 검토 호출에서 설정 준수 여부를 별도로 확인합니다. 위반 판정은 일반적인 완결 판정이 통과해도 승인하지 않으며, 기존 재집필 1회로 수정되지 않으면 회차와 기억을 반영하지 않습니다. 미래 결말은 중간 회차에서 조기 강제하지 않고 마지막 회차에 실제 발생했는지 확인합니다. 추가 API 단계 없이 기본 3회/최대 5회 호출을 유지합니다. 지시·검토 필드에 따른 토큰 증가는 있으며 실제 설정 준수율과 소비량은 생성 결과로 비교해야 합니다. 자동 회귀 테스트는 모킹된 검토 결과의 승인·재집필·실패 처리를 확인하며 실제 소설 품질 검증을 대신하지 않습니다. 이미 작성된 원고는 자동 수정하지 않습니다.

## 캐릭터 외모 설정

캐릭터 설정의 성별 아래 **외모** 입력란에 머리색·눈동자·얼굴·체형 등을 최대 1,000자로 입력할 수 있습니다. 선택 사항이며, 이미지 생성 후 확정된 외모는 대화·이야기에도 전달합니다. 설정으로 돌아가 입력값을 수정할 수 있고, 새 캐릭터 시작 시 초기화합니다. 실제 생성 품질 검증과 별개로 API 전달·화면 이동·초기화는 모킹된 자동 테스트로 확인합니다.

## 작업별 토큰 사용량

스튜디오 상단과 생성 팝업의 **토큰 사용량** 버튼은 제거했습니다. 내부 작업별 사용량 기록과 서버 로그는 유지합니다. 기존 사용량 집계의 범위는 다음과 같습니다. 대화의 말투 선택·본문·의상 판별, 이야기의 회차 설계·집필·재집필·전개 검증·기억 추출을 개별 호출로 기록하고 작업별·모델별 합계를 표시합니다. 대화·이야기는 각 호출 종료 시 OpenAI가 반환한 실제 `usage`로 갱신하며 생성 중인 토큰의 추정 카운터는 제공하지 않습니다. 이미지 설명·이미지 생성은 기존 JPEG 응답을 받은 뒤 함께 표시합니다. 기술 검증용 CAD 경로와 다른 탭·외부 도구 사용량은 이 패널의 범위에 포함하지 않습니다.

입력·출력·합계와 캐시 입력·추론 세부 수치를 표시하며 캐시·추론을 합계에 중복해서 더하지 않습니다. 실패한 원고의 이미 소비한 사용량도 남깁니다. 중단·통신 오류·API 사용량 미제공은 0으로 확정하지 않으며 미확인 사용량 때문에 실제 소비량은 표시 합계보다 클 수 있습니다. 무료 잔여량이나 청구액을 계산하는 기능은 아닙니다. 각 작업 ID·호출 ID·단계·실제 모델·응답 ID·상태·사용량·호출 소요 시간을 CSV로 내려받아 최적화 전후를 비교할 수 있습니다.

최근 300개 작업의 숫자·메타데이터만 `sessionStorage`에 보관합니다. 대화·캐릭터 초기화나 새로고침 후에도 기록을 유지하고, 탭을 닫거나 **완료 기록 비우기**를 누르면 삭제합니다. 진행 중 작업은 비우기에서 제외합니다. 서버 로그의 `ai-usage`에도 원고·프로필·키 없이 호출 메타데이터만 기록합니다. 측정을 위한 추가 모델 요청이나 프롬프트·출력 상한·검증 흐름 변경은 없습니다. 자동 검증은 모킹된 API 응답을 사용하며 실제 OpenAI 사용량 대조는 별도 수동 확인이 필요합니다.

## 개발 언어와 기술 스택

삽화는 최신 원고와 직전 회차의 장소 연결, 누적 요약을 함께 사용합니다. 장면 분석에서는 최초 이미지·생성 설명을 제외하고, 최종 이미지 생성에서만 원본을 인물 식별에 사용합니다. 직업이나 회상·다음 출근 계획이 현재 장소를 덮어쓰지 않도록 지시합니다. 집 도착→다음 날 식탁 사례는 실제 장면 분석 API로 집·실내복 선택을 확인했습니다. 이 검증은 이미지 렌더링 품질 확인과 구분합니다.

주 개발 언어는 **TypeScript**입니다. 화면은 React의 `.tsx` 컴포넌트로 작성하고, 서버 API와 소설·이미지·CAD 처리 로직은 `.ts`로 구현합니다. TypeScript의 `strict` 검사를 사용합니다. 스타일은 CSS, 설치·빌드 보조 스크립트는 JavaScript의 ES Modules(`.mjs`)를 사용합니다.

아래 버전은 `package.json`의 선언 기준입니다. 실제 설치 버전은 `package-lock.json`으로 고정하며 `npm ci`로 재현합니다.

## 코드 구조와 처리 방식

| 경로 | 담당 기능 |
|---|---|
| `app/ideal/` | 캐릭터 생성·대화·이야기 페이지와 공유 레이아웃 |
| `app/api/` | 서버 API: 캐릭터 이미지(`/api/characters`), 대화·소설(`/api/chat`), CAD 명세(`/api/generations`) |
| `components/` | React 화면, 실시간 응답 표시, 이미지 갤러리·배경·확대 보기 |
| `lib/chat/`, `lib/novel/` | 캐릭터 설정·말투·의상 감지, SSE 처리, 회차 설계·집필·검토·기억 갱신 |
| `lib/characters/` | 이미지 요청 검증, 그림체·장면·현재 장소 프롬프트 구성 |
| `lib/cad/`, `workers/cad.worker.ts` | CAD 명세 검증과 브라우저 Web Worker의 형상 생성·STEP 재검증 |
| `scripts/`, `public/wasm/` | CAD 실행 파일 준비 스크립트와 설치 시 복사되는 WASM 자원 |
| `tests/`, `tests/browser/` | 단위·API 테스트와 브라우저 E2E 테스트 |

브라우저는 React Context와 컴포넌트 상태로 캐릭터·대화·소설·갤러리를 관리하고, 서버 API에 필요한 문맥을 전달합니다. 서버는 OpenAI 키를 보관하고 입력 검증·콘텐츠 검사·모델 호출을 수행합니다. 대화는 SSE(`text/event-stream`)로 본문을 전달하고, 소설은 검증된 원고와 기억을 함께 확정하며, 이미지는 JPEG 바이너리로 반환합니다.

CAD의 무거운 연산은 서버가 아닌 브라우저 Web Worker에서 실행합니다. 캐릭터 기능은 현재 탭 메모리를 사용하고, 기존 판재 기술 검증 화면의 최근 작업은 `localStorage`를 사용합니다. 현재 MVP에는 로그인·서버 DB·영구 이미지 저장소를 연결하지 않았으며, Supabase 저장 기능은 향후 도입 대상으로 구분합니다.

## 실행

Node.js 22.18+ 또는 24 LTS를 사용합니다. `npm ci` 후 `.env.example`을 `.env.local`로 복사해 서버 환경변수를 설정하고 `npm run dev`를 실행합니다.

```env
OPENAI_API_KEY=OpenAI_서버_키
OPENAI_MODEL=gpt-6.1-sol
OPENAI_IMAGE_MODEL=gpt-image-2.5-sunburst
OPENAI_IMAGE_QUALITY=low
```

Vercel에도 같은 환경변수를 등록하고 재배포합니다. 키는 서버 전용이며 `NEXT_PUBLIC_*`에 넣지 않습니다. Cloudflare 설정, 접근 코드, Supabase 설정은 필요 없습니다. Supabase는 향후 저장 기능이 필요할 때 연결합니다. 캐릭터 이미지·입력 설정·대화·이야기는 `/ideal` 공통 레이아웃의 탭 메모리에 유지되어 세 화면 이동·브라우저 뒤로/앞으로 가기에도 보존됩니다. 새로고침이나 스튜디오 밖으로 이동하면 초기화됩니다. 캐릭터 없이 대화·이야기 주소에 직접 접속하면 생성 화면으로 안내하며 AI를 호출하지 않습니다. 응답 생성 중 다른 화면으로 이동하면 요청을 취소하고 미완료 응답은 다음 문맥에서 제외합니다.

## 기존 CAD 기술 검증 — `/technical/cad`

채팅 → OpenAI 프롬프트 정리 및 제한된 CAD 명세 → 브라우저 Worker의 OpenCascade.js → Three.js 미리보기 → STEP/JSON 다운로드.

- box / ellipsoid / cylinder / roof, 이동·회전·절삭, 최대 40개 부품을 지원합니다.
- 브라우저에서 실제 B-Rep을 만들고 STEP을 다시 읽어 유효성·치수를 검사합니다.
- STEP은 여러 솔리드의 조립체일 수 있습니다. 실사 피규어, 정밀 복제, 단일 융합 솔리드·즉시 출력 가능한 형상을 보장하지 않습니다.
- `/technical/plate`는 기존 판재 검증 화면입니다. 과거 구현 기록은 `docs/previous-implementation-notes.md`에 있습니다.
- WASM 약 23MB는 `postinstall`에서 준비합니다. 필요하면 `npm run prepare:cad`를 실행합니다.

## 캐릭터 생성 — `/ideal`

채팅 → OpenAI 콘텐츠 검사 및 캐릭터 설명 정리 → **GPT Image 2.5 Sunburst** → **원본 비율을 유지한 JPG 다운로드(최대 720×1280)**.

남녀 캐릭터의 톤앤매너를 `lib/characters/schema.ts`의 `CHARACTER_STYLES.female` / `CHARACTER_STYLES.male`에 각각 저장합니다. OpenAI가 대화의 요청 대상에 맞게 `styleProfile`을 선택하며 최신 성별 변경 요청을 우선합니다. 일반 수정은 이전 프로필을 이어갑니다. 성별 미지정·비인간 대상은 공통 스타일, 남녀가 함께 등장하면 혼합 스타일을 사용합니다. 머리 길이나 옷차림만으로 성별을 단정하지 않습니다.

- **여자 스타일:** 기존 모험가 샘플의 선명한 윤곽선, 풍부하고 따뜻한 채색, 셀 그림자와 부드러운 하이라이트, 장식의 정교한 마감을 참고합니다.
- **남자 스타일:** 새 첨부 샘플을 분석한 가늘고 섬세한 선화, 정제된 각진 얼굴 묘사, 저채도 회색·보랏빛 명암, 부드러운 셀 채색과 절제된 광택, 차분한 분위기를 참고합니다. 검은 머리·보라색 눈·귀걸이·초커·손짓을 자동으로 복제하지 않습니다.

결과 영역은 캐릭터 이미지만 바로 표시합니다. 그림체 참고·생성 프롬프트 탭과 샘플 이미지는 화면에 표시하지 않습니다. 실제 생성 스타일은 입력한 캐릭터 설정에 따라 자동으로 정합니다.

생성 이미지를 클릭하거나 키보드로 선택하면 화면 전체를 채우는 확대 보기 창을 엽니다. 이미지 비율을 유지해 전체 모습을 보여주며, 닫기 버튼·Esc·이미지 바깥 배경 클릭으로 닫습니다. 열려 있는 동안 배경 스크롤을 막고, 닫으면 원래 이미지 버튼으로 초점을 돌려줍니다.

인물·나이·성별·체형·의상·색상·표정·포즈·동반 생물·배경은 채팅 내용에 따라 정합니다. 샘플의 모험가·드래곤·의상을 자동으로 복제하지 않으며, 여성의 글래머러스함이나 남성의 섹시함도 자동 추가하지 않습니다. 2D 애니메이션 표현을 유지하고 모든 인물을 성인으로 고정하지 않습니다. 어린 캐릭터는 나이에 맞는 비성적인 디자인으로 표현합니다.

공통 스타일과 프롬프트 조립은 `lib/characters/schema.ts`에 있습니다. 입력으로부터 최대 800자의 ASCII 영문 subject를 정리해 스타일 지시와 결합합니다. 생성 프롬프트는 화면에 노출하지 않으며, 대화·이야기의 캐릭터 문맥에는 계속 반영합니다.

- 여자 스타일은 기존 샘플 PNG를 그림체 참고로 전달합니다. 남자·공통·혼합 스타일에는 여자 샘플 파일을 보내지 않습니다. 남자 스타일은 첨부 이미지를 분석한 저장 프롬프트로 적용합니다. 참고 파일이나 이전 결과가 없으면 Images generations, 있으면 Images edits를 사용합니다. 수정 시 직전 결과를 입력해 정체성과 변경하지 않은 디테일의 유지를 요청하며 완벽한 동일인 유지를 보장하지는 않습니다.
- API에 720×1280 생성 크기를 요청하고 세로형 9:16 구도를 지시합니다. sharp로 원본 비율을 유지한 최대 720×1280 JPEG로 변환합니다. 다른 비율의 응답에도 여백을 추가하거나 피사체를 자르거나 늘이지 않습니다. 실제 저장 크기를 응답 헤더와 다운로드 영역에 표시합니다. GPT Image에는 FLUX의 ‘4단계’ 옵션이 없습니다.
- 품질은 기존 저비용 선호에 따라 `low`가 기본이며 `OPENAI_IMAGE_QUALITY`로 변경할 수 있습니다. 프롬프트 정리와 이미지 생성에는 OpenAI 요금이 적용됩니다.
- multipart 요청 최대 약 2.65MB, 직전 JPEG 최대 2.5MB, 최대 13개 메시지, 인스턴스 전체 분당 3회로 제한합니다. 이는 분산 환경의 전역 비용 제한이 아닙니다.
- 결과는 binary JPEG로 반환합니다. 실패/취소 시 새 결과 다운로드를 비활성화하고, 취소한 입력은 복원합니다. 새 대화는 이전 이미지 참조까지 삭제합니다.

## 캐릭터 대화 · 이야기 만들기

캐릭터 특성의 성격 입력 위에 성별 선택박스를 두고 남성·여성 중 하나를 선택합니다. 선택은 새 캐릭터 생성 폼의 필수 항목이고, 수정·화면 이동 시 유지하며 전체 초기화 시 비웁니다. 생성 시 확정한 값은 이미지·대화·소설에 함께 전달됩니다. 기존 탭/API 프로필에 선택값이 없는 경우도 호환합니다. 외형은 컨셉과 명시된 설정을 따르며 성별에 따른 고정관념이나 외형 기본값을 임의로 추가하지 않도록 지시합니다.

이상형 화면에서 **캐릭터 이름·나이·성별·성격·컨셉 입력 → 캐릭터 생성 → 이미지 하단 아이콘 선택** 순서로 사용합니다. 장르 선택박스는 없으며 이미지·대화·이야기는 모두 막장드라마로 고정합니다. `lib/chat/character.ts`의 `FIXED_CHARACTER_GENRE`를 사용하고, 이전 탭이나 API 요청의 기존 장르 값도 서버 검증에서 막장드라마로 정규화합니다. 별도 키워드 입력 없이 특성과 컨셉으로 이미지를 만들며 수정도 같은 버튼으로 생성합니다.

생성(`/ideal`)·대화(`/ideal/chat`)·이야기(`/ideal/story`)는 독립된 페이지입니다. 각 페이지는 자신의 화면만 렌더링하고 공통 레이아웃이 캐릭터와 기록을 유지합니다. 상단의 이미지·대화·이야기 선택 메뉴는 표시하지 않습니다. 생성 이미지 바로 아래의 말풍선·책 정사각형 아이콘 버튼으로 대화·이야기 페이지로 이동합니다. 아이콘은 접근성 이름과 툴팁으로 구분합니다. 각 화면의 뒤로 버튼으로 이미지 결과로 돌아갈 수 있으며 브라우저 뒤로/앞으로 가기도 지원합니다. 대화·이야기는 생성 시 확정한 특성과 장르를 공유하고, 이야기 페이지에 처음 진입하면 첫 장면을 작성합니다. 막장드라마의 갈등·비밀·반전과 캐릭터 컨셉을 역할 지시에 반영합니다. 대화·이야기 상단의 캐릭터 정보에는 이름·나이만 표시하고 장르 문구는 숨깁니다. 모바일에서 생성 완료 시 이미지 결과로 스크롤합니다. 각 화면의 배경에 생성 이미지를 사용하고 글 영역에는 반투명 패널을 적용합니다.

`gpt-5.4-mini`의 Responses API 스트리밍으로 답변을 표시합니다. 마지막 성공 이미지의 생성 요청(후속 수정 포함), 요약, 생성 프롬프트와 입력한 캐릭터 설정을 매 요청에 전달합니다. 실제 이미지 픽셀을 모델에 보내지는 않습니다. 대화는 캐릭터의 1인칭 말투와 감정·관계를 유지하며 캐릭터가 사용자에게 직접 하는 말만 출력합니다. 강한 컨셉·막장드라마 분위기도 말의 내용과 어조에 반영하고 배경·날씨·행동·내면 서술·괄호 지문·사용자의 답변 대필은 넣지 않도록 합니다. 이야기는 별도로 서술과 대사가 있는 연재 소설로 이어집니다. 설렘·라이벌·비밀·갈등·반전 등을 활용하되 노골적인 성적 묘사는 피하고, 미성년 캐릭터는 나이에 맞는 비성적 콘텐츠로 제한하도록 지시합니다. 화면에 AI가 만드는 허구의 대화·이야기임을 표시합니다.

대화의 존댓말·반말은 컨셉과 관계를 기준으로 시작하고, 사용자에게 하는 말 전체에서 한 어투를 유지하도록 지시합니다. ‘반말해줘’, ‘존댓말로 말해주세요’처럼 명확한 요청은 즉시 반영하고, 간접적인 요청·관계 변화는 현재 어투와 완료된 대화 문맥을 함께 판단합니다. 사용자의 짧은 반말·존댓말 한마디만 따라 무작위로 전환하지 않도록 합니다. 선택된 어투는 성공적으로 끝난 답변과 함께 탭 메모리에 저장하므로 최근 20개 메시지 밖으로 전환 요청이 밀려나거나 이미지 화면으로 갔다 돌아와도 유지됩니다. 실패·취소된 답변은 어투를 바꾸지 않으며 새 대화·캐릭터 변경은 초기화합니다. 문맥 판단에는 같은 모델로 최대 500토큰의 추가 호출 1회가 필요하고, 명확한 전환 요청은 이 호출을 생략합니다. 본문은 계속 스트리밍하며 모델 지시를 사용하므로 모든 표현의 완벽한 일관성을 보장하지는 않습니다.

대화와 이야기의 기록은 서로 분리되며 화면을 오가도 유지됩니다. 각 화면의 ‘캐릭터 설정’은 공통 특성 입력으로 돌아갑니다. 특성 수정은 이미지를 다시 생성해야 대화·이야기에 적용되며, 입력 중에는 기존 기록과 확정한 특성을 유지합니다. 새 이미지 생성·수정은 양쪽 기록을 초기화하고, 상단 새 대화는 특성 입력·이미지·참조까지 초기화합니다. 각 화면의 새 대화는 해당 기록만 초기화합니다. 대화 메시지로 이미지를 자동 생성·수정하지는 않습니다.

대화·이야기는 화면 높이에 맞춘 읽기 화면을 사용합니다. 제목·캐릭터 정보는 한 줄 영역으로 모으고, 대화 입력창은 작게 유지해 본문에 공간을 우선 배분합니다. 이야기 화면에는 ‘삽화 생성’, 선택 입력인 ‘다음 이야기 컨셉’, ‘다음 이야기’ 버튼을 순서대로 배치합니다. 처음 진입하면 첫 장면을 작성하고, 이후 버튼을 누르면 완료된 이전 줄거리·인물 관계·캐릭터 설정·장르를 이어서 다음 장면을 작성합니다. 생성 중에는 버튼을 비활성화하고 실패하면 다시 누를 수 있습니다. 초기화 후에는 같은 버튼으로 첫 장면부터 시작합니다. 자동 요청 문구는 본문에 표시하지 않습니다. 이야기 영역의 머리말은 ‘함께 쓰는 이야기’ 제목만 표시하며 별도 안내 문구를 넣지 않습니다. 대화 본문은 16px, 이야기 본문은 17px와 넓은 행간으로 표시합니다. 모바일 키보드나 창 크기 변경 시 보이는 높이에 맞춰 조정합니다. 이야기는 새 회차의 첫 줄부터 읽으며 생성 중 아래로 강제 스크롤하지 않습니다. 대화도 위쪽 기록을 읽는 동안에는 새 응답이 와도 위치를 유지합니다.

대화 화면은 뒤로 가기·제목·캐릭터 정보·설정·새 대화를 하나의 상단 바로 합쳐 본문 높이를 더 확보합니다. 좌우 여백과 입력창도 줄이고, 데스크톱에서는 이전 1,100px 너비 제한을 해제해 채팅 영역을 넓힙니다.

이야기의 ‘삽화 보기’는 가장 최근 완료된 원고와 누적 요약·현재 상황을 구분해 원본 캐릭터 이미지와 함께 전달합니다. 원본은 얼굴·나이·머리카락·눈 등 인물 식별에 사용하고, 최신 회차의 한 장면에 맞춰 자세·손짓·표정·의상·소품·상호작용·구도를 새로 구성하도록 지시합니다. 이 지시는 프롬프트 정리와 최종 이미지 생성 양쪽에 전달하며, 배경만 바꾸거나 원본의 서 있는 자세를 복제하지 않도록 합니다. 명시된 의상 연속성은 유지합니다. 삽화는 최신 원고에서 현재 장소를 먼저 확인하고, 그 회차에 장소가 생략되면 요약·현재 상황으로 이어지는 장소를 확인합니다. 회상·이전 장면·다른 인물의 위치·미래 목적지는 현재 장소보다 우선하지 않습니다. 삽화 설명은 별도 필수 필드 sceneLocation(ASCII 영어 최대 300자)과 locationSource로 장소를 정리하며, 서버가 이를 최종 이미지 요청의 REQUIRED CURRENT SCENE LOCATION에 명시합니다. 따라서 800자 인물 설명에서 장소가 빠져 원본 배경으로 돌아가지 않도록 합니다. 현재 장소를 알아볼 수 있는 환경과 구도를 요구하며, 카페라면 원래 방에 커피잔만 더하지 않고 카페 좌석·카운터 등 식별 가능한 요소를 표현하도록 합니다. 대화는 유카타·기모노·치파오 등 의상 이름만 있어도 ‘의상 변경하기’를 표시합니다. 알려진 단어는 즉시 감지하고, 목록에 없는 의상은 마지막 사용자 메시지와 완료된 응답을 같은 모델로 최대 350토큰의 추가 호출 1회로 판별합니다. 의상 변경 버튼은 마지막으로 완료된 사용자 메시지와 캐릭터 답변 한 차례를 기준으로 활성화합니다. 최근 대화에 의상 언급이 없으면 과거에 의상 이야기를 했더라도 버튼을 비활성화하고, 다시 언급되면 활성화합니다. 의미 판별 결과가 없으면 해당 최근 두 메시지의 의상 단어만 확인하며 더 오래된 대화로 활성화하지 않습니다. 실패·중단된 응답은 최근 판별을 바꾸지 않습니다. 화면 이동 시 상태를 유지하고 새 대화에서 비우며, 판별 실패만으로 완료된 대화 본문을 버리지는 않습니다. 텍스트·이미지 생성 중에는 중복 이미지 요청을 막으며 실패·취소·지연 결과 차단과 갤러리 동작은 유지합니다.

### 캐릭터 대화의 인물·사건 기억

`character_chat_mvp_design.md`를 반영해 `lib/chat/memory.ts`에서 사용자(`user`), 캐릭터(`character`), 제3자(`npc_N`)를 고정 ID로 구분합니다. 최근 대화 순서는 유지하며, 최근 기록에서 오래된 발화가 빠져도 검증된 사실과 감정 상태를 다음 요청에 전달합니다. 장소·상황·관계·목표도 주체와 사건 유형이 있는 사실로 관리합니다. 캐릭터의 성격과 목표에 근거해 의견을 표현하고 무조건 동의하거나 매번 질문으로 끝내지 않도록 지시합니다.

본문 생성 호출 하나에서 비공개 전제 확인, 직접 대사, 기억 변경 제안을 함께 생성합니다. 스트리밍은 대사만 추출하며 내부 확인 결과나 기억 JSON을 본문에 표시하지 않습니다. 변경 제안은 인물 ID, 최신 사용자 발화 또는 캐릭터 답변의 정확한 인용, 사실 유형과 정정 대상을 검사합니다. 사용자 근거는 문장별 원문 ID를 선택하게 하고 서버가 실제 문장으로 복원해 바꿔 인용하는 오류를 줄입니다. 사용자 진술(`asserted`)과 캐릭터의 가상 행동(`simulated`)을 분리하고 추측(`inferred`)·근거 없는 변경·제3자의 임의 행동을 저장하지 않습니다. 같은 주체·사건 유형의 최신 진술과 명시적 정정을 우선합니다. 인용·ID 검사는 의미를 완벽하게 검증하지 않으므로 인물 혼동이나 사실 충돌을 전부 방지한다는 보장은 없습니다.

현실의 문자·전화·결제·예약 기능은 연결하지 않으며 완료했다고 주장하지 않도록 지시합니다. 실제 행동 요청이 있는 턴의 가상 행동 변경도 차단합니다. 대사와 기억은 응답 완료 후 함께 확정하고, 실패·취소 시 이전 기억을 유지합니다. 페이지 이동 시 보존하며 새 대화·캐릭터 재생성은 초기화합니다. 서버리스 환경이므로 설계서의 로컬 JSON 저장 예시 대신 기존 탭 메모리를 유지합니다. 최대 12명·24개 사실·10,000자의 기억으로 제한하고 오래된 사실부터 정리합니다. 새로고침하면 사라지며 무제한 장기 기억을 제공하지 않습니다. 기억 추출용 모델 호출을 별도로 추가하지 않고 기존 어투·의상 판별 호출을 유지합니다. 비공개 확인·대사·기억 패치는 기존 본문 출력 2,000토큰 예산을 공유합니다.

### 소설 전개 개선

이야기는 기본 **5편**으로 완결됩니다. 1편 도입, 2편 갈등 심화, 3편 전개 수렴, 4편 절정, 5편 결말을 계획합니다. 계획은 미래 목표이며 이미 일어난 사건으로 기억하지 않습니다.

‘다음 이야기 컨셉’을 입력하면 기존 원고와 누적 번호를 유지한 채 다음 생성부터 5편을 다시 계획합니다. **이야기 #3 뒤에 추가하면 #4~#8이 생성되고 #8에서 완결**됩니다. 완결 뒤에도 추가할 수 있고 빈 입력은 계획을 갱신하지 않습니다. 화면에는 ‘이야기 #N’과 ‘완결까지 N편’을 표시합니다. 성공할 때만 새 계획과 회차를 확정하고, 실패하면 회차와 컨셉 입력을 유지합니다.

마지막 회차는 사용자 설정과 핵심 갈등·주인공·관계의 결말을 검토합니다. 미완결이면 기존 재집필 1회로 수정하고, 재실패하면 상태를 반영하지 않습니다. ‘새 이야기’는 번호와 계획을 초기화합니다. 기존 10편 저장 계획은 읽을 수 있으며 다음 생성 시 과거 회차를 유지하고 5편 계획으로 교체합니다. 이미 5편 이상 진행했다면 추가 컨셉으로 새 5편을 시작합니다. 자동 검증은 모킹된 API를 사용하며 실제 5편 소설 품질은 별도 확인이 필요합니다. 아래 10편 검증은 이전 정책의 기록입니다.
